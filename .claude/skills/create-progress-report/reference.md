# 進捗報告パワポ生成 — 参照情報

## カラーパレット（Midnight Executive・固定）

| 役割 | 色 | 用途 |
|---|---|---|
| Primary | `#1E2761` | 見出し帯・表紙背景・強調テキスト |
| Secondary | `#CADCFC` | カード背景・表ヘッダー・アクセント面 |
| Accent | `#FFFFFF` | 本文背景・Primary上のテキスト |

補助として本文テキストは `#333333`、罫線は `#CADCFC` を基本とする。

## スライドプロファイル（個別ゼミ＝指導教員向け・固定）

- 専門用語は説明なしで使用可（LST、SHAP、Spatial CV 等）
- **結論ファースト**: 各スライドの冒頭に「このスライドの結論」を1行で置く
- 箇条書きは1項目1行・最大5項目
- 図表中心: 文章より図・表・数値を優先する
- LST は必ず摂氏（°C）で表記する

## レイアウト型

内容に応じて以下から選択する。1スライド1メッセージを原則とする。

### 表紙型

- タイトル「進捗報告（YYYY-MM-DD）」・氏名・研究題目
- Primary背景 + Accentテキスト

### アジェンダ型

- 報告項目の一覧（3-5項目）。ページ数が6枚以上の場合のみ使用

### カード型

- 複数の進捗（2-4件）を並列に紹介するサマリー用
- 各カード: Issue タイトルの要約（1行）+ 成果（1-2行）+ ラベル種別

### stat型

- 数値ハイライト用（例: 「有効画素 210万」「RF R² = 0.70」）
- 大きな数字 + 単位 + 補足1行を2-4個並べる

### 比較型

- 手法比較・before/after・シナリオ比較用（例: MLR vs RF、Random split vs Spatial CV）
- 2-3列の対比表または左右対比レイアウト

### 図表中心型

- 地図・グラフを大きく1枚配置 + 結論1行 + 出典（ファイルパス or Issue番号）
- QGIS生成画像・分析出力PNGを使用

### リスト型

- 「今後の予定」用。Issue番号・タイトル・マイルストーン・想定時期の表

## QGIS画像生成ガイド

QGIS-MCP で報告用の地図画像を生成する際は、以下に**必ず従う**（運用中に確認済みの制約・教訓）:

1. **プロジェクトを開く**: `load_project()` で対象都市のプロジェクト（例: `qgis/projects/hanoi.qgz`）を開く
2. **軽量テーマを適用**: `apply_map_theme()` では大規模レイヤーを含むテーマ（`Full` 等）を避け、`Limited` など軽量なテーマを選ぶ（クラッシュ対策）
3. **表示調整**: `set_layer_visibility()` で必要なレイヤーのみ表示する
4. **画像保存の方法に注意**:
   - `render_map()` は**レイヤーの表示/非表示切り替えを反映しないことがある**（キャッシュされた合成結果を返す場合がある）
   - 可視性を切り替えた場合は `get_canvas_screenshot()` または `execute_code` で `iface.mapCanvas().saveAsImage(path)` を使う
   - `render_map()` を使う場合は、出力画像に可視性変更が反映されているか毎回目視確認する
5. **後片付け（必須）**:
   - `save_project()` は**明示的に指示されない限り絶対に呼ばない**（ユーザーの作業中プロジェクトを壊さない）
   - 検証・調整で追加した一時レイヤーは `remove_layer()` で削除する
   - 可視性変更前の状態（元のテーマ）を再適用してからセッションを終える
6. **出力先**: `presentations/assets/YYYYMMDD_{内容}.png`（Git管理外）

## 報告履歴ログのスキーマ

`.github/progress_report_history.json`:

```json
{
  "reports": [
    {
      "date": "2026-07-07",
      "file": "presentations/progress_report_20260707_1030.pptx",
      "reported_issues": [70, 72, 80],
      "notes": "補足メモ（任意）"
    }
  ]
}
```

- `reported_issues` に含まれる Issue は、次回の Step 2 で除外候補に回す
- 履歴ログは Git 管理する（pptx 本体は管理しない）

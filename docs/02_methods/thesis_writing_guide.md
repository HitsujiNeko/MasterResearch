## 1. 目的と位置づけ

修士論文の原稿の書き方（ファイル構成・ビルド・文体・用語・数値・図表・引用・未確定箇所の印）を定める。

- **Markdown が正本、docx は生成物**とする。原稿は `thesis/` 配下の md に書き、Word（docx）は `scripts/build_thesis.py` で一方向に生成する。Word での直接編集は**提出直前の最終調整のみ**とし、それ以前に Word 側で直した内容は md に戻す
- `docs/` は研究記録の正本、`thesis/` はそこから作る成果物である。論文の記述は `docs/` の正本（手法・結果の文書）に依拠し、論文側で新しい事実を作らない。正本と論文で食い違いが見つかった場合は、正本を直してから論文に反映する

## 2. ファイル構成

```text
thesis/
├── metadata.yaml           # 題目・著者・目次見出し・図表番号の書式（pandoc-crossref）
├── .markdownlint.jsonc     # 節ファイル用の lint 設定（先頭行の h1 を求めない）
├── chapters/               # 原稿。相対パスの昇順に結合される
│   ├── 01_introduction/
│   │   ├── 00_chapter.md   # 章見出し「# 第1章　はじめに」のみ
│   │   ├── 01_background.md        # 「## 1.1　研究背景」
│   │   └── ...
│   ├── 02_study_area_data/ ...
│   └── 90_back_matter/     # 謝辞・参考文献・付録
├── figures/                # 論文専用の図（概念図など）
├── references/
│   └── extra.bib           # 文献 DB に登録しない文献（教科書・データの出典等）の手書きの書誌
├── templates/
│   ├── reference.docx      # 書式の雛形（生成物。手で編集しない）
│   └── thesis-ja.csl       # 引用・参考文献の書式（卒業論文に準拠）
└── build/                  # ビルド出力（Git 管理外。文献 DB から生成した references.bib も置かれる）
```

- **章はディレクトリ、節はファイル**とする。章見出しは各章の `00_chapter.md` にだけ書き、節ファイルは `## 1.1　…` から始める。項（`### 1.1.1　…`）は節ファイルの中に書く
- 章・節の番号は**見出しの文字列に手で書く**（pandoc の docx 出力は自動で番号を振らないため）。番号と題目の間は全角スペース 1 つとする（例: `## 1.2　既往研究における本研究の位置づけ`）。章を挿入・分割したときは、以降の章番号・節番号・ディレクトリ名の番号をまとめて付け直す
- 結果の章は、RQ ごとに章を分けるか 1 章にまとめるかを RQ1 の結果確定後に決める。それまでは `04_results/` 1 章として置く

### 2.1 節ファイルのメタ情報欄

各ファイルの冒頭に、次の HTML コメントを置く。docx には出力されない。

```markdown
<!--
見出し: 1.3　研究目的
状態: 未着手
依拠する正本:
  - docs/01_planning/research_guide.md
-->
```

| 項目 | 書き方 |
|---|---|
| 見出し | ファイル内の見出しと同じ文字列 |
| 状態 | `未着手`／`執筆中`／`初稿`／`確定` のいずれか |
| 依拠する正本 | 記述の根拠にした `docs/` の文書をリポジトリルートからの相対パスで列挙する。正本が更新されたときに追従が必要な節を特定するために使う |
| 目安（章ファイルのみ） | 章のページ数の目安 |

## 3. ビルド

### 3.1 準備

pandoc と pandoc-crossref は conda 環境 `masterresearch` に入っている（`environment.yml` で版を組で固定している）。既存の環境に追加するには次を実行する。

```bash
conda env update -n masterresearch -f environment.yml
```

### 3.2 docx の生成

```bash
python scripts/build_thesis.py
```

`python` は conda 環境 `masterresearch` の Python を使う（環境の外の Python では pandoc を探せない場合がある）。`thesis/build/thesis.docx` が生成される。目次は Word のフィールドとして出力されるため、Word で開いて更新するまでページ番号が入らない。目次を更新した docx と PDF を得るには `--pdf` を付ける（Windows かつ Word がある環境のみ）。

```bash
python scripts/build_thesis.py --pdf
```

図のファイルが見つからない（図が説明文に置き換わる）、参照先の無いラベルがある（本文に `¿fig:ラベル?` のように残る）といった pandoc・pandoc-crossref の警告は標準エラーに表示され、docx は生成される。警告は必ず解消する。`--strict` を付けると、警告があればビルドを失敗にする（提出前の確認に使う）。

### 3.3 書式（reference.docx）

書式は卒業論文に合わせ、`scripts/make_thesis_reference_docx.py` が pandoc 既定の雛形に値を適用して `thesis/templates/reference.docx` を生成する。書式を変えるときは**スクリプトの定数を直して再生成し、生成物もコミットする**（雛形を Word で直接編集しない）。生成物とスクリプトの一致や実際の docx 生成を確かめるテストは pandoc を要するため、CI（pandoc なし）では skip され、conda 環境でのローカル実行でのみ検証される。

| 項目 | 値 |
|---|---|
| 用紙・余白 | A4 縦、上 35／下 30／左 30／右 30 mm |
| 行 | 行グリッド 18 pt、本文の行間 1.5 行 |
| 本文 | ＭＳ 明朝＋Times New Roman 10.5 pt、左揃え、字下げ 1 字 |
| 見出し・図表題 | ＭＳ ゴシック 10.5 pt。章見出しの前で改ページする |
| 図 | 中央揃え。図番号「図-1」と題目を図の下に置く |
| 表 | 中央寄せ・格子罫線、表内は游ゴシック 11 pt。表番号「表-1」と題目を表の上に置く |
| 表紙 | 題目 24 pt、副題・著者・日付 18 pt |
| ページ番号 | フッター中央 |

## 4. 文体と表記

- **である調**で書く（「〜である」「〜した」）。「〜と思われる」のような主観表現は避け、根拠を示して「〜と考えられる」「〜を示唆する」とする
- **句読点は「，」「．」**（全角のカンマとピリオド）を使う。「、」「。」は使わない
- 英数字は半角、括弧は全角（`（`・`）`）とする。ただし数式・変数名・括弧内がすべて英数字の場合（例: `(2023)`）は半角でよい
- 略語は初出で正式名称を併記する（例: 地表面温度（Land Surface Temperature: LST））。以降は略語のみとする

## 5. 用語の統一

| 対象 | 規則 |
|---|---|
| 地表面温度 | 初出で「地表面温度（LST）」、以降は「LST」。**単位は必ず °C**（K で書かない） |
| 分析シナリオ | 和名と英名を初出で併記し、以降はどちらか一方に統一する（下表） |
| 範囲 | **ROI**（研究対象地域。基準となる空間範囲）と**有効域**（データを実際に信頼して使える範囲）を区別し、同一視しない。ROI の解析対象域を「全域」と呼ぶ場合も、ROI そのものではないことを初出で述べる |
| 研究課題 | 「RQ1」「RQ2」「RQ3」（1.4 節で定義した後に使う） |
| 衛星 | 「Landsat 8/9」のように半角英数字で書く |

分析シナリオの和名（暫定。第 3 章の初稿で確定する）:

| 英名 | 和名（案） | 使うデータ |
|---|---|---|
| Satellite Only | 衛星のみ構成 | 衛星由来データのみ |
| Limited | 公開データ構成 | 衛星由来データ＋公開 GIS データ |
| Full | 測量データ構成 | 衛星由来データ＋公開 GIS データ＋測量 GIS データ |

シナリオの定義の正本は [CLAUDE.md](../../CLAUDE.md) の最小用語集、各シナリオが成立する範囲は [research_guide.md](../01_planning/research_guide.md) のシナリオ表を参照する。

## 6. 数値

- 結果の数値は `docs/03_results/` の正本から転記し、その文書を節のメタ情報欄の「依拠する正本」に記す。論文の執筆中に再計算した値を直接書かない
- 有効桁は次を目安とし、同じ表・同じ段落の中では桁を揃える

| 量 | 桁 |
|---|---|
| LST・気温（°C） | 小数第 1 位 |
| 決定係数・相関係数・SHAP の寄与 | 小数第 2 位（差が小さく比較に必要な場合は第 3 位） |
| 割合（%） | 小数第 1 位 |
| 面積・距離 | 有効数字 3 桁程度 |

- 数値と単位の間は半角スペースを入れる（例: `30 m`、`32.5 °C`）。ただし `%` は数値に続けて書く（例: `12.3%`）
- 範囲は「〜」で書く（例: `30〜300 m`）

## 7. 図表と数式

pandoc-crossref の記法で書く。番号は文書全体の通し番号で自動的に振られ、題目の位置（図は下、表は上）も自動で決まる。

```markdown
@fig:lst_map に LST の分布を示す．

![2022 年 9 月 6 日の LST 分布](images/xxx.png){#fig:lst_map width=80%}

| 変数 | 内容 | 単位 |
|---|---|---|
| NDVI | 正規化植生指数 | – |

: 説明変数の一覧 {#tbl:variables}

$$ \mathrm{LST} = \beta_0 + \beta_1 \mathrm{NDVI} $$ {#eq:model}
```

- 本文では `@fig:ラベル`・`@tbl:ラベル`・`@eq:ラベル` で参照する（「図-1」「表-1」「式(1)」と出力される）。番号を手で書かない
- ラベルは英小文字・数字・`_` で、内容が分かる名前にする（`fig:lst_map`。`fig:1` のような番号は使わない）
- 図のパスは `thesis/` からの相対（論文専用の図 `figures/...`）か、リポジトリルートからの相対（分析の図 `images/...`）で書く。分析の図は `images/` の正本を参照し、`thesis/figures/` に複製しない
- 図の出典（他者の図を引用する場合）は題目の末尾に書く
- 表の単位は列見出しか題目に書き、セルには数値だけを書く

## 8. 引用と参考文献

- 先行研究を引用するときは**原典（PDF）で記述を確認してから**書く。構造化要約（`docs/04_archive/02_structured_summaries/`）は文献探しの手がかりであり、引用の根拠にしない
- 引用文献がまだ決まらない・原典で確認できていない箇所は、著者名・発行年を仮に書いたうえで `[要出典]` を付けて残してよい

### 8.1 引用の書き方

本文中の引用は pandoc の引用記法で書き、番号を手で書かない。参考文献リストはビルド時に自動で作られ、`thesis/chapters/90_back_matter/02_references.md` の `::: {#refs}` の位置に出力される。

```markdown
LST の算出には SMW 法を用いた[@S1]．
多重共線性の扱いは既往研究に従う[@S12; @S13]．
```

- 文献 DB の論文は **S 番号を引用キー**にする（`[@S1]`）。複数の文献は 1 つの角括弧に `;` で区切って並べる（`[@S12; @S13]`。角括弧を 2 つ続けて書かない）
- 引用は句点「．」の前に置く。docx では上付きの「1)」となり、複数は「2)3)」と並ぶ。番号は本文で初めて引用した順に振られ、同じ文献を再び引用すると同じ番号になる
- 参考文献リストには**本文で引用した文献だけ**が載る（文献 DB の全件は載らない）
- 存在しない引用キーは警告になり、本文に `キー?`（例: `nokey?`）が上付きで残る。`--strict` 付きのビルドで確認する
- ページ指定（`[@S1, p. 5]`）は使わない。卒業論文と同じく番号だけを出力する書式のため、ページ指定は警告なしに消える。ページを示す必要がある場合は本文に書く

### 8.2 参考文献リストの書式

書式は `thesis/templates/thesis-ja.csl` が卒業論文に合わせて定める（区切りは全角の「：」「，」、末尾は「．」）。

| 種別 | 例 |
|---|---|
| 雑誌論文 | `1) Ermida, S. L., Soares, P., Mantas, V., Göttsche, F.-M. and Trigo, I. F.：Google Earth Engine Open-Source Code for …，Remote Sensing，Vol.12，No.9，p.1471，2020．` |
| 書籍 | `2) 益田晴恵：都市の水資源と地下水の未来，京都大学学術出版会，2011．` |
| Web ページ・データ | `3) 大阪府：地下水質調査結果，https://…（参照 2025/2/25）．` |

- 欧文の著者は全員を「姓, 名の頭文字」で並べ、最後の 1 人の前に「and」を置く
- 和文の著者は卒業論文と同じく「益田晴恵，根本達也，新谷毅」と全角の「，」で並べる（書き方は 8.3 の手書きの書誌を参照）
- ページ範囲は `pp.80-90`、論文番号の雑誌（MDPI 等）は `p.1471` と表示する（pandoc の BibTeX 読み込みに論文番号の欄が無いため、ページ欄に論文番号を入れる）
- 題名は原典の表記（大文字小文字を含む）のまま出力する

### 8.3 書誌の置き場所

| 文献 | 書誌の置き場所 | 引用キー |
|---|---|---|
| 査読論文（文献 DB に登録するもの） | [papers_database.csv](../04_archive/01_metadata/papers_database.csv)（収録と S 番号）＋ [papers_bibliography.csv](../04_archive/01_metadata/papers_bibliography.csv)（引用用書誌） | S 番号（`S1`） |
| 教科書・報告書・データの出典・Web ページ等 | `thesis/references/extra.bib`（手書きの BibTeX） | 英小文字・数字・`_` で内容が分かる名前（`usgs_landsat_c2`） |

- **引用用書誌（papers_bibliography.csv）**: 文献 DB の各論文につき 1 行。全著者（BibTeX の `姓, 名 and 姓, 名` 形式）・原典表記の題名・誌名・年・巻・号・ページ（範囲は `80-90`、論文番号は `1471`）・DOI を、**Crossref と原典 PDF の両方で照合して**書き（DOI の無い文献・Crossref から取得できない文献は PDF のみ）、照合元・照合日を残す。2026 年 2 月に ChatGPT で作った構造化要約には事実誤りがあるため、要約経由の書誌は使わない。文献 DB に論文を追加したら、論文で引用するかどうかにかかわらず、この CSV にも行を足す。`/add-paper` で登録すれば行の追記まで行われる（`/add-paper` を使わずに文献 DB を直した場合は手で足す・直す。行が無い・ずれているとビルドとテストが失敗する）
- ビルドのたびに `scripts/make_thesis_bib.py` の処理で両 CSV から `thesis/build/references.bib` が生成される（コミットしない）。生成前に行の過不足と年・題名・誌名・DOI の一致を検査し、ずれがあればビルドが失敗する。単独で生成する場合は `python scripts/make_thesis_bib.py` を実行する
- **手書きの書誌（extra.bib）**: 書誌は原典（書籍の奥付・報告書の表紙・Web ページ）で確かめてから書く。漢字の氏名・機関名は `{{益田晴恵}}` のように二重の波括弧で囲む（姓・名に分けると名の後ろに「.」が付くため）。和文の著者が複数いる場合は `{{益田晴恵，根本達也，新谷毅}}` と全角の「，」で区切って 1 つの波括弧にまとめる（`and` で区切ると欧文の「, … and」になるため）。Web ページ・データの出典は `@online` とし、`url` と `urldate`（参照日）を書く。S 番号の形のキー・重複キーはビルドが失敗する。書き方の例はファイル冒頭のコメントにある

## 9. 未確定箇所の印

未確定の箇所には次の印を本文にそのまま書く。docx にもそのまま出力されるため、印刷物でも見落とさない。

| 印 | 意味 |
|---|---|
| `[要出典]` | 根拠となる文献が未確定、または原典で未確認 |
| `[TBD:結果]` | 分析結果の確定待ち（値・図表・解釈） |
| `[TBD:内容]` | 上記以外の未確定事項。`内容` に何が未確定かを書く（例: `[TBD:提出年月日]`） |

未着手の章・節には見出しの直後に `[TBD:本文]` を置き、書き始めたら消す（空の節が印の一覧から漏れないようにするため）。

残っている印は次のコマンドで一覧できる。**提出前に 0 件にする**。

```bash
grep -rn -e "\[要出典\]" -e "\[TBD:" thesis/chapters/ thesis/metadata.yaml
```

未定義の参照（`¿…?`）は md ではなく生成された docx に現れるため、`--strict` 付きのビルドで確認する。

## 10. 変更の運用

論文の原稿の変更は、章・節ごとに Issue を立てて進める。レビューの扱い（変更区分 D の手順を適用し、PR で一括確認する）は [task-workflow.md](../../.github/task-workflow.md) の「変更区分（唯一の定義）」を正本とする。

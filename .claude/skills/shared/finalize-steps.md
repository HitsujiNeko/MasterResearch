# スキル終端手順 共通リファレンス（ファクトチェック→lint→承認→コミット）

**役割**: ドキュメント生成系スキル（add-paper / report-results / create-progress-report 等）が共有する終端手順の**唯一の正本**。各スキルは本手順に固有の差分（コミットメッセージ等）を加えて使用する。

---

## Step A: ファクトチェック

ドキュメント・スライドに記載した**すべての数値・固有名詞**（R²・RMSE・件数・平均値・著者名・年・DOI・データセット名・期間等）について、「記載値 / 出典ファイル」の対応表をユーザーに提示し、確認を得る。

- 数値は必ず出典ファイル（JSON / CSV / PDF）を Read で開いて転記する。**会話の記憶・過去ログ・再計算による転記は禁止**（転記ミスの主因）
- 出典が確認できない値は「未確認」「要確認」と明示し、推測で埋めない

## Step B: lint

変更した `.md` ファイルに対して `npx markdownlint-cli2` を実行し、エラーを修正する。

## Step C: 承認・コミット

1. 変更ファイル一覧をユーザーに提示し、承認を得る
2. 承認後にコミットする。コミットメッセージは `{type}: {変更内容の要約} (#{Issue番号})` 形式（各スキルの指定に従う。対応する Issue がない場合はユーザーに確認のうえ番号を省略する）

## Step D: push の扱い

push は [task-workflow.md](../../../.github/task-workflow.md) の「push の条件」に従う: **(a) タスク完了フロー内の PR 作成時、(b) ユーザーの明示指示 — の2条件のみ**。スキル単体の実行では push しない。

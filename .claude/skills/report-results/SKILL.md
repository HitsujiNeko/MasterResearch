# 分析結果ドキュメント生成スキル

分析実行後の結果整理を定型化し、`docs/03_results/` への結果ドキュメント追加と索引更新の漏れを防ぐ。

## 大原則

- **数値は必ず出力ファイルから読み取る**: R²・RMSE・件数・平均値などの数値は、対象の JSON / CSV を Read で開いて転記する。会話の記憶・過去ログ・再計算による転記は禁止（転記ミスの主因）
- **LST は摂氏（°C）で記載する**
- **有効カバレッジと ROI 全体を混同しない**: 「ROI全体の平均」ではなく「品質管理後の有効画素での平均」のように、集計母数を明示する
- **解釈・考察は断定しない**: 「〜と考えられる」「〜の可能性がある」等のたたき台として書き、最終判断はユーザーに委ねる

## 実行手順

以下のチェックリストをコピーして進捗を追跡する:

```text
- [ ] Step 1: 対象の確認
- [ ] Step 2: 出力ファイルの読み取り
- [ ] Step 3: 結果ドキュメントの生成
- [ ] Step 4: docs/README.md の更新
- [ ] Step 5: ファクトチェック・lint・コミット
```

### Step 1: 対象の確認

以下をユーザーに確認する（会話の流れから明らかな場合は確認結果として提示する）:

1. **対象の分析**: 実行した分析スクリプト（例: `src/analysis/analysis_rq3_satellite_only.py`）と実行条件
2. **出力ファイル群**: `data/output/` 配下の対象ファイル（Globで候補を提示する）
3. **対象RQ**: RQ1 / RQ2 / RQ3 のどれに対応する結果か
4. **ドキュメント名**: `docs/README.md` の命名規則に従う（小文字スネークケース、内容が分かる名前。例: `rq1_variable_importance.md`）
5. **新規作成か既存更新か**: 既存ドキュメント（例: `satellite_only_analysis_results.md`）への追記の場合は、既存構成を維持して差分を統合する

### Step 2: 出力ファイルの読み取り

1. summary / results 系の JSON・CSV を Read で読み、ドキュメントに載せる数値を抽出する
2. 図（PNG）はファイルパスの一覧を作成する（`data/` 配下は Git 管理外のため、パス参照として記載する）
3. 読み取った数値は「ファイルパス → 値」の対応を保持し、Step 5 のファクトチェックで提示できるようにする

### Step 3: 結果ドキュメントの生成

`docs/03_results/satellite_only_analysis_results.md` を構成の型として、以下の標準構成で生成する（分析の性質に応じてセクションの追加・省略可）:

（以下テンプレート中のリンクは生成先 `docs/03_results/` からの相対パスです。SKILL.md 自身からは解決しません）

```markdown
# {分析名} 分析結果

**最終更新**: YYYY-MM-DD  
**関連ドキュメント**: [analysis_workflow.md](../02_methods/analysis_workflow.md), [research_guide.md](../01_planning/research_guide.md)  
**対象RQ**: RQ{n}（{RQの短い説明}）

## 1. 今回の位置づけ
（研究全体・シナリオ比較の中でこの結果がどこに位置するか）

## 2. 今回実施したこと
（番号付きリストで処理の流れ）

## 3. データと処理条件
（採用データ、入力ファイルパス、品質管理条件、モデル設定、出力ファイル一覧）

## 4. 基本結果
（表を中心に。数値は出力ファイルからの転記のみ）

## 5. 解釈と考察（たたき台）
（先行研究・既存結果との対比。断定しない）

## 6. 次のステップ
（この結果を受けた次の分析・確認事項）
```

### Step 4: docs/README.md の更新

以下をすべて更新する（更新漏れは `/check-docs-consistency` で検出される）:

1. 「📊 03_results - 研究結果」のカタログ表に行を追加（新規作成時）
2. 03_results セクションの「ドキュメント詳細」に概要を追加（新規作成時）
3. ディレクトリ構造図の `03_results/` 配下（新規作成時）
4. 変更履歴に1行追加・末尾の「最終更新」を当日に更新

既存ドキュメント更新の場合は、カタログ表の概要・変更履歴のみ更新する。

### Step 5: ファクトチェック・lint・コミット

[../shared/finalize-steps.md](../shared/finalize-steps.md) の共通終端手順（ファクトチェック→lint→承認・コミット→push条件）に従う。本スキル固有の差分:

- コミットメッセージ: `docs: {分析名}の結果ドキュメントを追加 (#{Issue番号})`

## 注意事項

- 出力ファイルが見つからない・数値が読み取れない場合は、該当箇所を「未確認」として残し、推測で埋めない
- 図の妥当性確認（可視化が結果と整合しているか）が必要な場合は、QGIS MCP や PNG の Read での目視確認をユーザーに提案する
- 学会アブストラクト・スライドへの転用は本スキルの範囲外（結果ドキュメントを正本として別途作成する）

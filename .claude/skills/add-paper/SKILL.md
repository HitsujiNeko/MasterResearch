# 論文追加スキル

構造化要約を `docs/04_archive/` の文献データベース（3層構造）に登録する一連のファイル操作を定型化する。

## 実行手順

以下のチェックリストをコピーして進捗を追跡する:

```text
- [ ] Step 1: 入力の確認・要約の準備
- [ ] Step 1.5: 書誌照合（Crossref）
- [ ] Step 2: S番号の採番・要約ファイルの作成
- [ ] Step 3: papers_database.csv への追記
- [ ] Step 4: README・関連ドキュメントの更新
- [ ] Step 5: ファクトチェック・lint・コミット
```

### Step 1: 入力の確認・要約の準備

入力の形態に応じて分岐する。

| 入力 | 対応 |
|---|---|
| 構造化要約Markdown（claude.ai で生成済み） | そのまま Step 2 へ。テンプレートとの構成差分があれば整形する |
| 論文PDF | Read でPDFを読み、`docs/04_archive/templates/structured_summary_template.md` に沿って要約を自分で作成する |
| 書誌情報のみ（タイトル・著者・DOI等） | 入手可能な情報のみでテンプレートを埋め、未確認項目は「未確認」と明記する |

必須項目（著者・年・タイトル）が欠けている場合は推測せず、ユーザーに確認する。

### Step 1.5: 書誌照合（Crossref）

S番号・ファイル名を確定する**前**に、正式書誌を機械照合し転記誤りを防ぐ。

> **注**: 当初 DOI なし論文の検索には OpenAlex を想定していたが、2026-07-15 時点で OpenAlex API はクレジット制の課金体系に移行しており（`https://api.openalex.org/works` が 429 + 課金メッセージを返す）、無認証・無料での利用を前提にできない。そのため Crossref の書誌検索（`query.bibliographic=`、認証不要）に一本化する。将来 OpenAlex が無料枠を再提供した場合はフォールバック先として追加を検討する。

1. **DOI がある場合**:
   - DOI を正規化する（`https://doi.org/` プレフィックスを除去し、小文字化する）
   - `curl -s https://api.crossref.org/works/{DOI}` で生 JSON を取得する（WebFetch は要約を経由し数値・巻号等の転記精度が落ちるため使用しない）
   - 取得したタイトル・著者・発表年・掲載誌・巻号と、入力（要約・PDF転記値）を照合する
   - 差分があれば対応表（項目｜入力値｜Crossref取得値）で提示し、どちらを採用するかユーザーに確認する
   - ベトナム人著者名等、Crossref の given/family 分割が姓の判定と一致しない場合があるため、ファイル名用の筆頭著者姓は機械的に採用せずユーザーに確認する
2. **DOI がない場合**:
   - `curl -s "https://api.crossref.org/works?query.bibliographic={タイトル（URLエンコード）}&rows=3"` でタイトル検索し、DOI の特定を試みる
   - 上位候補が複数返るため自動採用しない。候補（タイトル・著者・年・DOI）を提示し、ユーザーが同一論文と確認したうえで DOI を採用する
   - 見つからない、またはユーザーが同一論文と確認できない場合は従来どおり「未確認」と明記する（小規模会議録等は Crossref 未収載のことが多い）
3. **API が失敗した場合・DOI が未登録の場合**: 照合をスキップし、その旨を記録する（登録フロー自体は止めない）
4. 照合結果（実施日・一致/不一致/スキップの別）は Step 2 で要約ファイル末尾に記録する

### Step 2: S番号の採番・要約ファイルの作成

1. `docs/04_archive/02_structured_summaries/` の既存ファイル名（`S{番号}_{著者}_{年}.md`）から最大番号を取得し、次の番号を採番する
2. `S{番号}_{筆頭著者姓}_{出版年}.md` として要約ファイルを作成する（例: `S9_Zhang_2023.md`）
   - 著者姓は英字表記・特殊文字は除去（例: Onačillová → Onacillova）
3. テンプレートのセクション構成をすべて含める。空欄になるセクションは削除せず「該当なし」「未確認」と記載する
4. 末尾の作成日・最終更新は当日の日付とする
5. Step 1.5 の照合結果を末尾に1行で記録する（例: `書誌照合: Crossref 2026-07-15 一致` / `書誌照合: Crossref 2026-07-15 候補採用` / `書誌照合: スキップ（DOI未登録）`）。CSV への列追加は行わない

### Step 3: papers_database.csv への追記

`docs/04_archive/01_metadata/papers_database.csv` の末尾に1行追加する。

- 列構成はヘッダー行に従う（ID, 著者, 年, タイトル, 掲載誌, 主目的, データ種別, 主要手法, 対象地域, DOI_URL, PDF有無, 重要度, RQ1関連, RQ2関連, RQ3関連, キーワード, メモ）
- カンマを含むフィールドは二重引用符で囲む。キーワードはセミコロン区切り
- RQ関連度は既存行の表記（◎○△＋短い補足）に合わせる
- 重要度（A/B/C）は要約内容から提案し、ユーザーに確認する
- エンコーディングはUTF-8を維持する（Editツールで追記すれば維持される）

### Step 4: README・関連ドキュメントの更新

以下の記載箇所をすべて更新する（更新漏れがドキュメント整合性チェックで検出される）:

1. `docs/README.md`
   - 「先行研究一覧（S1-S8）」の一覧に追加（範囲表記 S1-S8 も S1-S{新番号} に更新）
   - 「構造化要約（現存ファイル）」のリンクリストに追加
2. `docs/04_archive/README.md`
   - ディレクトリ構造図の `02_structured_summaries/` の記載を更新
3. `docs/04_archive/previous_studies_report.md`
   - 「1. 先行研究一覧」の表に1行追加
   - 本文の詳細セクション（S{番号}章）の追加は任意。ユーザーに「詳細セクションも作成するか」を確認し、承認された場合のみ要約から生成する

### Step 5: ファクトチェック・lint・コミット

[../shared/finalize-steps.md](../shared/finalize-steps.md) の共通終端手順（ファクトチェック→lint→承認・コミット→push条件）に従う。本スキル固有の差分:

- ファクトチェック対象: 要約中の数値（R²、RMSE、寄与率等）・著者名・年・DOI
- 照合済み書誌（著者・年・誌名）が papers_database.csv・要約ファイル・ファイル名の3層で一致していることを確認する
- コミットメッセージ: `docs: 先行研究S{番号}（{著者} {年}）を追加 (#{Issue番号})`

## 注意事項

- 論文内容の解釈（RQ関連度・重要度・本研究への示唆）は提案にとどめ、最終判断はユーザーに委ねる
- 同一論文の重複登録を防ぐため、Step 2 の前に papers_database.csv でタイトル・DOIの重複を確認する
- claude.ai（Claude Projects）側での要約生成手順は `docs/04_archive/claude_project_instructions.md` を参照

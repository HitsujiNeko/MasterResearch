## 3. ラン間で共通の処理条件

以下の条件は全ランで共通である。ランによって変わる項目は、2節の台帳へ列として置く。

### 3.1 ROI・スケール・格子・観測

- ROI: ハノイ
- スケール: **30m**
- 格子: 30m正準グリッド（全 **3,739,454行**）。衛星データのみと同一の格子であり、`cell_id` で結合する
- 観測: **`2023-07-07T03:23:05Z`（Landsat 8）で全ラン共通**

### 3.2 建物高さ列の補完

`BUILD_H_MEAN`/`BUILD_H_MAX` は、高さが取れる建物が1つも無いセルでNULLになる。「建物が無い」の判定は `BUILD_COV == 0`（被覆率）単独ではなく、`BUILD_COV == 0 AND BUILD_DEN == 0`（棟数密度も0）で行う。

`BUILD_COV` はfineグリッドへのラスタ化による近似であり、`gis_data_buildings.md`「小さい建物の取りこぼし」の実測によれば、30mでは建物の重心が存在するセル（`BUILD_DEN > 0`）の**14.0%**で `BUILD_COV == 0` になる（GBAの建物の80.7%が100m²未満で、fine 10mセルの中心を1つも含まない場合に被覆率へ寄与しないため）。ただし `BUILD_DEN` も逆方向に取りこぼす（重心が隣セルにあり輪郭だけが張り出した大きい建物）ため、`BUILD_DEN` 単独でも「建物が無い」の判定はできない。

この2条件のANDに基づき、`BUILD_COV == 0 AND BUILD_DEN == 0` のセルのみ「建物が無い ⇒ 建物高さ0m」として0補完し、`BUILD_COV > 0` または `BUILD_DEN > 0` なのに高さNULL（真の欠落）のセルは補完せず、後段の非NULL要求フィルタで除外した。

| 母集団 | 補完セル数 | 比率 |
|---|---|---|
| データセット全体（3,739,454） | 2,781,918 | 74.4% |
| ラン1のフィルタ後母数（3,274,665） | 2,387,100 | 72.90% |
| ラン2のフィルタ後母数（1,309,830） | 422,265 | 32.24% |

**比率は母集団を明示して読む必要がある。** 建物が存在するセルへ限定するラン2で比率が大きく下がるのは定義どおりの挙動である。

**補完はどの建物高さ構成でも同一に行う。** 下記の `--building-height` は「補完後の2列のうち、どれをモデルへ投入するか」だけを切り替えるものであり、補完の判定条件・件数には影響しない。

#### 建物高さ列の構成（`--building-height`）

`BUILD_H_MEAN` と `BUILD_H_MAX` は同一の建物ポリゴンから集計した高さであり強く相関するため（Pearson +0.985・6.2節）、2列とも投入するとVIFが危険水準を大きく超える（6.4節）。投入する高さ列は `--building-height` で切り替える。ラン別の値は2節の台帳「建物高さ」列を正本とする。

| 値 | 投入する列 | 備考 |
|---|---|---|
| `both` | `BUILD_H_MEAN` + `BUILD_H_MAX` | ラン5の構成 |
| `mean` | `BUILD_H_MEAN` | **採用構成（既定）**。セル内の平均建物高さ |
| `max` | `BUILD_H_MAX` | セル内の最高建物高さ |
| `pc1` | `BUILD_H_PC1` | 2列を標準化して合成した第1主成分（合成列） |

全構成に共通する仕様は次のとおり。

- **非NULLを要求するフィルタ列は構成に依らず高さ2列のまま**であり、母数・分析サンプルは構成間で完全に一致する（2.1節）
- **相関行列の対象列は構成に依らず一定**（拡張後の全候補列）であり、`BUILD_H_PC1` は対象に加えない。診断すべきは元の2列の相関そのものであるため（6.2節）
- `pc1` の主成分は**分析サンプル全体で1回fitする**（Spatial CVのfold内ではfitし直さない）。符号は `BUILD_H_MEAN` への寄与が正になる向きへ揃える。loadings・寄与率・標準化統計は `*_results.json` の `building_height_pc1` に記録する。実測値と fold 内 fit を採らなかった根拠は6.4節
- 出力ファイル名の `_bh_{構成}` は **`both` のときだけ付けない**。既定を変えても `both` で実行済みのランの出力名が動かないようにするためである（3.7節）

### 3.3 品質管理（フィルタ条件）

全ランに共通して、以下を満たすセルを残す。

- マスク段（`required_mask_columns`）: `IN_ANALYSIS_AREA == 1`・`VALID_POP_<選択した人口ソース>_MASK == 1`・`VALID_NTL_MASK == 1`
- 指定した説明変数列と `LST` が非NULL（建物高さ補完後）。分光指数は、投入するかどうかや水指数の構成に依らず、**新世代（ラン12〜15）では NDVI・NDBI・NDWI・MNDWI の4列**、旧世代（ラン1〜11）では MNDWI 列が無いため3列に非NULLを要求する
- `LST_VALID_RATIO >= 0.5`

**人口・夜間光は非NULL要求フィルタではなく有効域品質列で判定する**（1.2節）。このため後段の脱落内訳（3.8節）には人口・夜間光の要因が現れない。品質列による実効的な脱落の規模はそちらで別途示す。

`VALID_GIS_MASK == 1` を追加で課すかどうかはランごとに変わるため、台帳の「フィルタ条件」列で示す。

`VALID_GIS_MASK == 0` は全件 `no_gis_feature`（`build_dataset.py` のコメントにより「分析上は0として扱ってよい」観測結果）であり、`missing_gis_data` は0件だった。**ただしこの「0件」は、建物パラメータテーブルが正準グリッドの全セルに結合できたこと（テーブル結合の完全性）を示すのみであり、GBAが現地の建物を漏れなく検出できていること（データそのものの正確性・有効カバレッジ）までは検証していない**（`BUILD_COV`/`BUILD_DEN` は結合の有効域外でも常に0.0を返す設計のため、結合が成功していれば `missing_gis_data` は構造的にほぼ0件になる。3.2節で述べた小規模建物の取りこぼしはこの「0件」では検出できない）。

この限界を踏まえたうえで、**主結果では `VALID_GIS_MASK` を課さず有効域全体を対象**とする（`VALID_GIS_MASK == 0` のセルを「GIS特徴量が観測結果として0」として扱う判断自体は妥当であり、テーブル結合の完全性は確認済みのため）。判断の妥当性は6.6節で検証する。

#### 水指数ブロックの構成（`--water-index`）

`NDVI` と `NDWI` はどちらも近赤外（NIR）の反射を反対の符号で使うため構造的に強く相関し（Pearson −0.972・6.2節）、両方を投入すると VIF が危険水準を大きく超える（6.5節）。分光指数ブロックのうち水指数の扱いは `--water-index` で切り替える。ラン別の値は2節の台帳「水指数」列を正本とする。

| 値 | 投入する分光指数 | 備考 |
|---|---|---|
| `ndwi` | `NDVI` + `NDBI` + `NDWI` | ラン1〜12 の構成 |
| `none` | `NDVI` + `NDBI` | **採用構成（既定）**。ラン13 |
| `pc1` | `NDBI` + `VEG_WATER_PC1` | `NDVI` と `NDWI` を標準化して合成した第1主成分（合成列）。ラン14 |
| `mndwi` | `NDVI` + `NDBI` + `MNDWI` | `NDWI` を NIR を含まない `MNDWI`（緑と短波赤外）へ差し替え。ラン15 |

全構成に共通する仕様は次のとおり。建物高さの構成（3.2節）と同じ設計である。

- **非NULLを要求するフィルタ列は構成に依らず4列**（`NDVI`・`NDBI`・`NDWI`・`MNDWI`）であり、母数・分析サンプルは構成間で完全に一致する（2.1節）
- **相関行列の対象列は構成に依らず一定**であり、`MNDWI` を含み `VEG_WATER_PC1` を含まない。`NDVI` × `MNDWI` を全ランで実測するためである（6.2節）
- `pc1` の主成分は**分析サンプル全体で1回fitする**。符号は `NDVI` への寄与が正になる向き（合成列が大きいほど植生が多い）へ揃える。loadings・寄与率・標準化統計は `*_results.json` の `vegetation_water_pc1` に記録する。fold 内で fit しない判断は建物高さ（6.4.4節）を踏襲し、全体fitとfold内fitの一致を `tests/analysis/test_analysis_rq3_limited.py` の `TestAddVegetationWaterPc1` が固定している
- 出力ファイル名の `_wi_{構成}` は **`ndwi` のときだけ付けない**（3.7節）
- 分光指数を投入しない `--variable-set coverage` とは併用できない。`coverage` のランでは `*_results.json` の `water_index_mode` が `null` になる

### 3.4 サンプリング

- 適用順序: 建物高さ補完 → フィルタ → サンプリング → ブロック割り当て（ブロック割り当てを先にすると各ブロックのセル数が不均等に減り、fold のサイズ均衡が崩れるため）
- サンプル数: `100,000`
- 乱数シード: `42`
- サンプル内の建物高さ補完セル数: ラン1 **72,657件**（72.66%）、ラン2 **32,012件**（32.01%）

  この値は3.2節の「フィルタ後母数における補完セル数」とは異なる母集団（フィルタ後の全件 vs 10万件サンプル）に対する集計であり、両者は一致しない（比率はほぼ一致: ラン1 72.90% vs 72.66%、ラン2 32.24% vs 32.01%）。研究記述で引用する際はどちらの母数か明記すること。

### 3.5 モデル設定

- 学習 / テスト: `80,000 / 20,000`（random split、`test_size=0.2`）
- 目的変数: `LST`（°C）
- MLR: 説明変数・目的変数の両方を標準化（標準化偏回帰係数として解釈）
- RF: `n_estimators=300`, `min_samples_leaf=5`
- Spatial CV:
  - `5-fold`（Group K-Fold、group = 空間ブロックID）
  - ブロックサイズ: `2,700m`
  - 非空ブロック数: 台帳の「ブロック」列（10万件サンプル後ベース）
- SHAP: 評価サンプル `2,000`、background `500`

**本ドキュメントの既存ランの `*_results.json` には、乱数シード（3.4節）・RF決定木本数等の実行パラメータが記録されていない**（実行パラメータ記録の導入前に実行したため。値は本節・3.4節の記述を正とする）。既定値が変われば引数を省略した再実行では同じ条件を再現できないため、再現時は `--random-state 42 --rf-trees 300` を明示する。導入後のランでは `*_results.json` の `run_parameters` に記録される（キー構成は衛星データのみと共通。記録範囲の判断は `src/common/run_parameters.py` のmodule docstringを正本とする）。既存ランは再実行・追記修正を行わない（記録値を後から書き足すと、実行時に実際に使われた値であることを結果ファイル自身が保証できなくなるため）。

**Spatial CV の R² の読み方（重要）**: ブロックサイズ 2,700m では LST の空間自己相関を断ち切れていない。本ドキュメントが報告する Spatial CV の R² を**「未知の場所への汎化性能」として読んではならない**（同一ROI内・空間的に近い場所への内挿性能として読む）。実測の根拠は3.9節を、主採用の観測での測定と採用した設計は [spatial_cv_design_results.md](../spatial_cv_design_results.md) を参照する。

### 3.6 分散0の特徴量列の除外

説明変数のうち分析サンプル内で分散が0になる列は、VIF算出・モデル学習の前に除外する。定数列を残すと、分散0の列は決定係数を定義できないため `compute_vif` が `inf` を返し、**完全共線と同じ形で報告される**が、これは実体のある共線性ではなく定数列に起因する偽陽性であり、多重共線性の診断そのものを汚染するためである。

GLC を土地被覆ソースとするラン（1・2・4〜9）では `LULC_BARE_COV` が除外された。ハノイROIのGLC_FCS30Dには裸地クラス（200・201・202）の画素が1つも存在せず、**全セルで厳密に0.0になる**（実測100.00%・5.5.1節）ためである。**Esri を用いたラン（10・11）では裸地画素が存在するため除外は発生しない**（Esri の変数数が1つ多い理由）。除外した列名は各ランの `*_results.json` の `dropped_constant_features` に記録している。

判定は母集団ではなく分析サンプル（10万件）に対して行う。VIF も同じサンプルで算出するため判定対象を揃える必要があるが、代償として母集団での出現頻度が低いクラスはサンプル依存で除外されうる。

### 3.7 出力ファイル

`data/output/limited/20230707_032305/`（ラン12〜15 は `data/output/limited/20230707_032305_water_index/`）に、台帳の「出力接頭辞」ごとに次を保持する（1.1節）。

**出力接頭辞の組み立て規則**: `{データセットstem}_{変数セット}[_bh_{建物高さ}][_wi_{水指数}][_pop_{人口ソース}...][_gismask]`。角括弧の部分は条件付きで付く。人口ソースは**既定（WorldPop2020単独）と同じなら付けない**。建物高さは**`both` という値のときだけ付けない**（既定を基準にすると、採用構成の変更にあわせて既定を変えた瞬間に新しい既定の出力名が `_bh_` 無しの形へ移り、`both` で実行済みのランの出力ファイルと衝突するため）。水指数も同じ理由で **`ndwi` という値のときだけ付けない**（既定の `none` で実行したランには `_wi_none` が付く）。`_gismask` は感度分析の印として末尾に置く。

- `*_sample_100000.csv`: サンプリング結果（**Git管理外**）
- `*_feature_importance.csv`: 係数・重要度・VIF
- `*_spatial_cv_folds.csv`: fold別評価値
- `*_model_comparison.png`, `*_feature_importance.png`, `*_spatial_cv.png`: 可視化
- `*_shap_importance.csv`, `*_shap_summary.png`, `*_shap_bar.png`, `*_shap_dependence_{変数名}.png`: SHAP関連
- `*_results.json`: 全結果の要約。水指数の構成は `water_index_mode` キーに記録される（ラン12以降）。実行パラメータは `run_parameters` キーに記録される（3.5節参照。記録の導入前に実行した既存ランは持たない）。どのコード・環境・入力から生成したかを示す来歴メタデータは `provenance` キーに記録される（`--diagnose-only` の `*_diagnostics.json` にも付与。内容は [data_management_guide.md](../../02_methods/data_management_guide.md) 7.5節を参照。導入前の既存ランは持たない）。**ラン12〜15 の `provenance.git` は `dirty: true` だが、実行時に未コミットと表示されていたのは改行コード（CRLF）だけが異なるファイルであり、内容の差分は無かった**（実行時のコミットは水指数の構成切り替えの導入時点。それ以降のコード差は既定値の変更のみで、`--water-index` を明示すれば現行コードで同じ構成を再実行できる）

### 3.8 フィルタ脱落と欠損値処理の診断

**本節は分析結果ではなく、分析へ進んでよいかの判断根拠を記録するものである。** 建物高さの帰属方式変更と人口・夜間光の nodata 対処方針の変更（いずれも1.2節）が実データへ同時に適用されるため、結果が変わったときに原因を事後に切り分けられない。そこで分析実行の前に検証フェーズを置き、数値診断と目視確認で欠損値処理の妥当性を確かめた。

対象データセットは `dataset_limited_20230707_032305_hanoi_30m.gpkg`（3,739,454行・42列。正準グリッドの行数と一致）。生成コマンドは次のとおり。

```bash
python -m src.analysis.build_dataset --city hanoi --scale 30 --scenario limited --tables idx_20230707_032305 lst_20230707_032305 --name limited_20230707_032305
```

Esri 版（ラン10・11）は主ソースとの列名衝突を避けるため `--scenario` を使わず全テーブルを明示列挙する。

```bash
python -m src.analysis.build_dataset --city hanoi --scale 30 --tables mask_roi build_gba road_osm elev_fabdem lulc_esri2022 ntl_viirs2023 pop_worldpop2020 pop_landscan2020 pop_landscan2023 idx_20230707_032305 lst_20230707_032305 --name limited_esri_20230707_032305
```

**本節の数値の出所**: 「要因別内訳」「目的変数分布の切り詰め」「空間的な集中」と、ファネルの「正準グリッド全体」「品質列を通過」「説明変数の非NULL要求を通過」の3行、および「0補完の実測」の建物高さ行は、各ランの `*_results.json`（`filter_dropout` / `building_height_fill`・Git管理下）から読める。**ファネルの「ROI内」「LST非NULL」の2行、「品質列による実効的な脱落」「0補完の実測」の人口行、「水域被覆の偏り」は `*_results.json` に含まれず、上記コマンドで生成したデータセット（`.gitignore` 対象）への直接集計である**（再測定にはデータセットの再生成が要る）。

`filter_dropout.dropped_summary` は `target_available` 以降の脱落しか対象にせず、**品質列（マスク段）で落ちるセルを評価しない**。品質列による脱落は水域寄りに偏るため、LST有効なROI内セルを母集団として水域被覆の階級別に残存率を確認した。

| 水域被覆（`LULC_WATER_COV`） | 母集団 | 最終母数 | 残存率 | うち品質列で除外 |
|---|---|---|---|---|
| なし（0） | 3,063,075 | 3,016,341 | 98.47% | 28,285 |
| わずか（0 < cov < 0.1） | 27,926 | 26,150 | 93.64% | 1,672 |
| 部分（0.1 <= cov < 0.5） | 60,798 | 56,502 | 92.93% | 4,116 |
| 優勢（0.5 <= cov < 0.9） | 49,877 | 45,349 | **90.92%** | 4,384 |
| 水域優位（cov >= 0.9） | 135,301 | 130,323 | 96.32% | 4,077 |
| 水域被覆が欠測 | 342 | 0 | 0% | 256 |
| **全体** | 3,337,319 | 3,274,665 | 98.12% | 42,790 |

**確認された偏り**: 品質列で除外されたセルの水域被覆は平均0.199で、母集団平均0.056の3.5倍である。除外セルの平均LSTは33.57°Cで最終母数の35.52°Cより約2°C低く、**低温側が優先的に削られる方向**である。

**偏りの規模**: 水域被覆の平均は母集団0.05633に対し最終母数0.05449であり、相対3.3%の減少にとどまる。最も残存率の低い階級（0.5–0.9）でも90.92%が残る。

**0補完方針との関係**: 残存率の凹みは0補完が作ったものではない。水域優位セル135,301のうち**53,955セルは0補完によって初めて最終母数へ残った**もので、0補完が無ければ水域優位セルの残存率は96.32%から56.4%へ落ちる。方針変更は水域の取りこぼしを大幅に**減らした**側である。

**残る凹みの由来**: 最も残存率の低い0.5–0.9の階級は「過半が水域だが閾値0.9に満たない」セルであり、1.2節の「水域と断定できない陸地」に対応する。水域と断定できないセルへ人口0を与える誤りを避けるため、あえて補完せず除外すると決めた範囲であり、**閾値0.9の意図した帰結**である。

**この偏りは分光指数の差し替えでは解消しない**。脱落の出所は品質列（人口・夜間光の有効域）であって投入する指数の選択ではない。また `NDVI`・`NDBI`・`NDWI` は19,633セルで完全に同時にNULLになり（各 `exclusive_null_count` が0）、欠測がバンド個別ではなく観測シーンのフットプリント・雲マスクに由来することを示す。したがって水指数を差し替えても脱落するセルは変わらない（新世代で追加した `MNDWI` も、欠損位置が `NDWI` と画素単位で完全に一致することを実測した・3.10節）。**本節の偏りは解消済みの課題ではなく、結果の解釈時に持ち越す前提条件として扱う**（低温側・水域寄りのセルが母集団からわずかに薄いこと）。

#### 判定

建物高さ・人口・夜間光の3つの変更はいずれも意図した方向に効いている。**母集団の性格**についても、建物被覆の平均0.0841・市街地被覆の平均0.2129と、事前の推計（それぞれ0.0833・0.211）にほぼ一致する。

一方で、上記「水域被覆の偏り」のとおり**最終母数は水域寄り・低温側のセルをわずかに薄く含む**。これは欠損値処理の誤りではなく閾値0.9の意図した帰結であり、規模も相対3.3%にとどまるため、現行方針のまま分析へ進む判断とした。ただし**解消済みの課題としてではなく、結果の解釈時に持ち越す前提条件として扱う**。

水指数の共線性（上記「多重共線性」）については、`NDVI` と `NDWI` がどちらもNIRに支配され符号が逆であることに由来する構造的な相関であり、分析実行後に水指数ブロックの構成比較として対処した（6.5節）。この対処は投入する列の選択であり、水域セルの抽出条件（閾値0.9）は動かしていない。比較の基盤となる母集団は本節の判断のまま固定している。

### 3.9 分析実行前のモデル前提の精査

3.8節の欠損値処理とは別に、**前処理とモデル構築の前提が成り立っているか**を分析実行の前に確認した。以下は実装の誤りを報告するものではなく（誤りは見つかっていない）、**結果を読むときの前提条件**を明示するものである。

#### 確認して問題がなかった点

- **標準化のリークが無い**: `StandardScaler` は学習データのみで `fit` し、評価データは `transform` のみを適用する（`src.common.regression_models.fit_linear_regression`）
- **土地被覆の単体制約を処理済み**: 7クラスの面積率は**全行で厳密に合計1.0**になる（実測100.0000%）。そのまま投入すると完全な線形従属になるため、参照クラス（ROIで最大の農地 `LULC_CROP_COV`）を除外している（3.6節・`LULC_REFERENCE_COLUMN`）
- **定数列の除外**: `LULC_BARE_COV` はハノイROIのGLCに裸地画素が無く全行で0のため除外され、VIFの偽陽性（`inf`）を防いでいる
- **サンプリングは乱数抽出**（`DataFrame.sample`・シード42）であり、`cell_id` 順の系統抽出ではない
- **Spatial CV のグループ分離**: `GroupKFold` により同一ブロックのセルが学習側と評価側へ分かれることはない

#### Spatial CV のブロックサイズと R² の関係

ブロックサイズを変えて out-of-fold R² を比較した（分析サンプル10万件、RFは診断用に決定木100本。**絶対値ではなくブロックサイズ間の相対変化を読む**ための測定であり、3.5節の本番設定 300本の値とは一致しない）。

| ブロックサイズ | ブロック数 | RF R² | fold間sd | 線形 R² |
|---|---|---|---|---|
| ランダム分割（空間非考慮） | — | 0.7954 | — | 0.6462 |
| **2,700m（本ドキュメントの設定）** | 501 | **0.7596** | 0.045 | 0.6447 |
| 5,400m | 145 | 0.7417 | 0.024 | 0.6319 |
| 8,100m | 72 | 0.6806 | 0.106 | 0.6008 |
| 13,500m | 30 | 0.6748 | 0.126 | 0.5710 |
| 21,600m | 17 | 0.5461 | 0.205 | 0.5228 |

**再現手順**: 上表の各行は `--block-size-m` を切り替えた次のコマンドで再現できる（`--rf-trees 100` が診断設定、サンプル10万件・シード42は既定値）。「ランダム分割（空間非考慮）」の行は同じ実行の `random_split` の値である。**本表は分析ランではなく診断のための測定であり、出力は一時ディレクトリへ出して追跡下には置いていない**（台帳にも載せない）。

```bash
python -m src.analysis.analysis_rq3_limited --block-size-m 5400 --rf-trees 100 --output-dir <一時ディレクトリ>
```

**このコマンドは旧世代のデータセット・当時のコードでのみ上表を再現できる。** 現行のスクリプトは既定の水指数が `none` に変わり、MNDWI 列の無い旧世代のデータセットを拒否するため、そのまま実行すると別の構成・別の母数での測定になる（1.4節）。

**ブロックを大きくするほど R² が単調に下がる。** LSTのセミバリオグラムでも、2,700m 地点のセミバリアンスは全体分散の69%にとどまり、sillに達するのは15〜30kmである。すなわち**2,700mのブロックでは空間自己相関を断ち切れていない**。

線形モデルとの対比がこれを裏づける。線形モデルはランダム分割0.6462に対し2,700mで0.6447とほぼ変わらない（位置を記憶できないため）のに対し、**RFは0.7954から0.7596へ0.036下がる**。RFだけが近傍の空間的近さから利得を得ていることを示す。さらに「RFが線形を上回る幅」はブロック拡大とともに +0.115（2,700m）→ +0.080（8,100m）→ +0.023（21,600m）と縮む。**RFの優位の相当部分は、非線形性の捕捉ではなく空間自己相関の利用である可能性が高い。**

ただし**低下のすべてが空間リークとは限らない**。ブロックを大きくすると保留域が大きな連続地域になるため、リークの除去と空間的非定常性（地域が変われば説明変数とLSTの関係自体が変わる）が混在する。fold間sdが0.045から0.205へ膨らむのはこのためであり、**大きいブロックでの個々の数値は信頼できない**。信頼できるのは単調に低下するという傾向である。

**結果の読み方（重要）**: いずれの解釈でも帰結は同じで、**本ドキュメントが報告する Spatial CV の R² を「未知の場所への汎化性能」として読んではならない**。同一ROI内・空間的に近い場所への内挿性能として読む。ブロックサイズ自体の見直し（適切なサイズ・緩衝帯の要否）は [spatial_cv_design_results.md](../spatial_cv_design_results.md) で行った。

**主採用の観測での測り直し（2026-11-04 追記）**: 上の表と本文は 032305 の記録として残す。セミバリオグラムはスクリプトで算出し直し、数値と測定条件は [spatial_cv_design_results.md](../spatial_cv_design_results.md) 3節・4.1節を出典とする。032305 の 1,800〜2,700m のラグの値は 0.685〜0.691 で「69%」を再現し、「sill に達するのは15〜30km」も矛盾しない（3本の平均曲線で、比が 1 に達するのは 18,450m、最大は 31,950m）。032358 では同じラグが 0.743〜0.751、比が 0.95 に達する距離が 12,150m である。

一方、**ブロックサイズに対する低下は 032358 ではかなり弱い。** RF は 2,700m の 0.839 から 21,600m の 0.797 への低下にとどまり、RF が線形を上回る幅も +0.073 から +0.064 への縮小にとどまる（共通評価セル・2シード平均・RF 300本）。**上の「RFの優位の相当部分は、非線形性の捕捉ではなく空間自己相関の利用」という読みは、032358 では支持されにくい。** 032305 と違う理由は切り分けていない（未確認）。

#### 建物高さ0補完の構造的な従属

`BUILD_H_MEAN == 0` のセルは、`BUILD_COV == 0 かつ BUILD_DEN == 0` のセルと**一致率100.000000%で一致する**（分析サンプルの72.66%）。3.2節の補完規則そのものが `BUILD_COV == 0 AND BUILD_DEN == 0` を判定条件としているため、**補完後の建物高さ列のゼロ部分は他の2つの建物変数から完全に決まる**。

VIFはこれを検出できない（`BUILD_H_MEAN` のVIFは1.72）。VIFが測るのは線形従属であり、ここでの従属は「ゼロか否か」という指示変数の水準で生じているためである。結果として、`BUILD_H_MEAN` の標準化係数・重要度は**「建物の有無」（`BUILD_COV`・`BUILD_DEN` と共有する情報）と「建物がある場合の高さ」を分離できない**。非ゼロ部分の分布は平均5.73m・中央値4.82m・最大137.7m、列全体の歪度は11.1である。**建物高さの寄与の小ささ（5.1節・6.4節）を「高さがLSTに影響しない」と読んではならない。**

#### 目的変数と説明変数の算出式上の結合

LST は SMW 法で算出しており、地表面放射率を**同じシーンの NDVI から**求めている（[gee_calc_LST.md](../../02_methods/gee_calc_LST.md) 5.2節）。このため **`NDVI` と `LST` の間に算出式に由来する代数的な依存がある**。032305・032358 のどちらの LST もこの方式で算出されたことを確認した（[lst_emissivity_sensitivity_results.md](../lst_emissivity_sensitivity_results.md) 3章・4.1節）。

**訂正（2026-11-13）**: 本項の旧記述は「USGS Level-2 の地表面温度プロダクト（`ST_B10`）をスケーリングして用いており、コード内で植生指数から放射率を算出してはいない」としていたが、誤りだった。確認した 2 観測（032305・032358）の LST の算出には、`ST_B10` のスケーリング（`calculate_lst_simple`）は使われていない（他の観測は未確認）。

放射率を NDVI に依存させない対照（ASTER GEDv3 の静的な放射率）で LST を作り直して比べた結果、主採用の観測では**平均 |SHAP| の上位 5 変数の順位は変わらなかった**（下位の変数どうしの入れ替わりや、Permutation 重要度などでの一部の順位の変化はあった）が、NDVI の寄与の大きさ、特に植生域で冷却効果に見える傾きは弱まった。RQ1 では順位の頑健性を記述し、NDVI の寄与の大きさは限界として扱う（同ドキュメント 6章）。

#### 変数分布の性質

分析サンプルにおけるゼロの割合と歪度は次のとおりで、線形モデルの係数は多くの変数で実質的に「有無」の対比を測ることになる。

| 変数 | ゼロ率 | 歪度 |

### 3.10 衛星指標の再生成（MNDWI の追加）

**本節は分析結果ではなく、新世代のデータセット（1.4節）の来歴と検証を記録するものである。** 水指数 `MNDWI` を得るには元の反射率が必要であり、手元の tif（指数3バンドのみ）からは計算できないため、同じ観測（032305）の衛星指標を GEE から再エクスポートした。

#### 再生成の手順

1. `src/gee/gee_calc_satellite_indices.py` に `MNDWI` を追加し（算出式は [gee_calc_satellite_indices.md](../../02_methods/gee_calc_satellite_indices.md) 3章）、対象期間を 2023-07-07 に絞った一時設定で実行した。既存の設定 CSV（2023-01-01〜2024-12-31）のまま実行すると、全シーンの再エクスポートと Git 管理下の統計 CSV の上書きが起きるためである。Drive の出力先は既存フォルダと分けた（`INDICES_hanoi_2023_MNDWI`）
2. 同日の2シーン（032305・032329）が出力されたが、**差し替えたのは 032305 のみ**である（032329 はアーカイブ側の旧記録が参照している）
3. 30m の idx テーブルとデータセットを作り直した。90m・300m の idx テーブルは再生成していない（旧 tif 由来のまま残る・7節）

```bash
python -m src.analysis.urban_params.run --city hanoi --satellite-file data/satellite/indices/2023/INDICES_Landsat8_20230707_032305Z.tif --scales 30
python -m src.analysis.build_dataset --city hanoi --scale 30 --scenario limited --tables idx_20230707_032305 lst_20230707_032305 --name limited_20230707_032305
```

#### 旧 tif がクリップ前の出力だった（判断事項）

再エクスポートの準備中に、旧 tif（2026-04-06 出力）が**ROI ポリゴンでのクリップを導入する前の出力**であることが分かった。有効画素 6,145,969 のうち 2,582,877 画素（42%）が ROI ポリゴンの外にある。一方、同じ観測の LST の tif はクリップ済みであり、**ROI の境界にかかるセルでは、旧世代の指標が LST より広い範囲の画素を平均していた**ことになる。

現行コード（クリップあり）で再エクスポートするか、旧 tif と同条件（クリップなし）で再現するかを検討し、**クリップありを採った**（研究者判断）。ROI の外は分析に使わないためである。代償として、ラン1〜11 は新世代のデータセットでは再現できなくなった（1.4節）。

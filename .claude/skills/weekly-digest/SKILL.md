# 週次進捗ダイジェストスキル

GitHub Project と git 履歴から過去7日間の進捗を集計し、専用Issueに時系列で蓄積する。
ゼミ資料作成（`/create-progress-report`）の素材・停滞Issueの検知にも使う。

## 実行手順

### Step 1: 進捗データの収集

1. **Project 全アイテムの取得**: [../shared/github-project-api.md](../shared/github-project-api.md) の「Project 全アイテムの取得」に従い、ページネーションで全ページを取得する（クエリ・フィールド名・使用禁止コマンド・日本語処理の注意はすべて同ファイルが正本）

2. **分類**（基準日 = 実行日）:
   - **完了**: 「完了日」が過去7日以内
   - **新規着手**: 「開始日」が過去7日以内（完了済みを除く）
   - **進行中・保留**: 現在のステータスが「進行中」「保留」
   - **長期滞留**: 「進行中」のまま開始日から21日以上経過したもの（注意喚起用）

3. **commit 履歴**:

   ```bash
   git log --since="7 days ago" --date=short --pretty=format:"%h %ad %s" main
   ```

4. **新着文献検索**（OpenAlex）: 研究テーマ関連の過去7日の新着論文を検索し、`papers_database.csv` と突合して未登録候補を得る。出力先はスクラッチパッド（探索メモはリポジトリ非コミット）。

   ```sh
   python -m src.literature.paper_watch \
     --top 20 \
     --output "{スクラッチパッド}/paper_watch_candidates.csv"
   ```

   - プロジェクトルートから `python -m` 形式で実行する（`python src/...` は import を壊すため使わない）。
   - 候補が多い場合は `--min-score {閾値}` で足切りできる（スコアはキーワードの機械的一致度）。
   - **API 不通・取得失敗時**: スクリプトは標準エラーに「新着文献検索をスキップしました」と出して終了コード0で戻る。この場合はダイジェストの当該セクションをスキップ扱いにする（Step 2 参照）。digest 全体は止めない。

### Step 2: ダイジェストの生成

以下の構成でMarkdownを生成する。事実（Issue・commitの記録）のみで構成し、推測による進捗評価は書かない。

```markdown
## 週次ダイジェスト（YYYY-MM-DD 〜 YYYY-MM-DD）

### ✅ 完了（{n}件）
- #番号 タイトル（ラベル / 完了日）

### 🚀 新規着手（{n}件）
- #番号 タイトル（ラベル / 開始日）

### 🔄 進行中・保留（{n}件）
- #番号 タイトル（ステータス / 開始日）

### ⚠️ 長期滞留（21日以上「進行中」）
- #番号 タイトル（開始日: YYYY-MM-DD）※該当なしの場合はセクションごと省略

### 📝 主な commit（{n}件）
- ハッシュ 日付 メッセージ（多い場合は代表10件に絞り、件数を明記）

### 📚 新着文献候補（{n}件）
- スコア / タイトル（年・誌名） / DOI ※`paper_watch` の上位候補を数件（既定5件目安）掲載する

---
🤖 このコメントは /weekly-digest スキルにより作成されました。
```

**📚 新着文献候補セクションの扱い**（Step 1 の新着文献検索の結果に応じる）:

- **未登録候補あり**: スコア降順で上位数件（5件を目安）を掲載する。各行は「スコア・タイトル（年・誌名）・DOI」。候補が多い場合は件数を明記して上位のみ掲載する。**候補の提示のみを行い、採否判断・精読・登録は研究者が [/add-paper](../add-paper/SKILL.md) で行う**旨を1文添える。
- **0件**: 既存の長期滞留セクションと同方式で**セクションごと省略**する。
- **検索スキップ（API 不通等）**: セクションは残し、`※新着文献検索は今回スキップされました（OpenAlex 接続失敗）` と明記する。digest 全体は止めない。

### Step 3: 専用Issueへの投稿

1. 専用Issueを検索する:

   ```bash
   gh issue list --state open --search "研究進捗 週次ダイジェスト in:title" --json number,title
   ```

2. **存在しない場合（初回のみ）**: タイトル「研究進捗 週次ダイジェスト」・ラベル `workflow` でIssueを作成する。本文には「このIssueは週次ダイジェストの蓄積専用。/weekly-digest スキルがコメントを追記する」と記載する。プロジェクトへの追加・優先度設定は行わない
3. ダイジェストを [../shared/github-project-api.md](../shared/github-project-api.md) の「日本語テキストの安全な処理」に従い、一時ファイル経由の `--body-file` で投稿する
4. 投稿したコメントのURLをユーザーに報告する

## 注意事項

- 同一週に複数回実行した場合は上書きせず、新しいコメントとして追記する（実行日を明記しているため履歴として共存可能）
- リポジトリへのコミットは発生しない（Issueコメントのみ）
- 集計対象は Project 登録済みIssueのみ。Project未登録のIssueが疑われる場合はその旨を注記する
- 新着文献候補は探索メモをコミットせず（出力 CSV はスクラッチパッド）、digest には上位数件のみ掲載する。登録・精読は研究者が `/add-paper` で行う

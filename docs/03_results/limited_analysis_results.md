## 1. 位置づけ

RQ3 では Full / Limited / Satellite Only の3シナリオを比較する。Satellite Only は cell_id結合の新経路で既に成立済み（[satellite_only_analysis_results_cellbased.md](satellite_only_analysis_results_cellbased.md)）であり、本ドキュメントは公開GISと衛星指標を組み合わせた **Limited** シナリオの評価結果を記録する。Full シナリオ（測量GISの追加）は本ドキュメントの対象外（未着手）。

### 1.1 数値を比較してよい範囲

本ドキュメントは**複数のランを台帳（2節）に並べて記録する**。ランの追加にあたって、数値を直接比較してよいかどうかは次の基準で判断する。

- **比較してよい**: パイプライン（`build_dataset` → `analysis_rq3_limited`）と正準グリッドが同一で、観測日・スケールが揃っているラン。台帳の同一グループ内がこれにあたる
- **比較してはならない**: 格子やパイプラインが異なるもの。[satellite_only_analysis_results_cellbased.md](satellite_only_analysis_results_cellbased.md) との比較は特徴量集合が異なるため参考にとどめる（6.7節）
- **標本まで揃っているか**を併せて確認する。母数が揃っていても抽出された10万件が同一とは限らず、母数が数十セル違うだけで標本はほぼ別物になる（2.1節）

### 1.2 数値の正本

**変数重要度・VIF・相関行列のフル表は本ドキュメントに貼らない。** 変数が増えるとフル表が読めなくなるため、次のファイルを数値の正本とし、本文には比較に必要な要約（上位変数・危険水準を超えたVIF・ラン間の差分）のみを載せる。

| 種別 | ファイル |
|---|---|
| 標準化係数・RF重要度・Permutation重要度・VIF | `{接頭辞}_feature_importance.csv` |
| SHAP 平均絶対値 | `{接頭辞}_shap_importance.csv` |
| 全結果の要約（母数・除外列・診断範囲を含む） | `{接頭辞}_results.json` |
| fold別評価値 | `{接頭辞}_spatial_cv_folds.csv` |

いずれも `data/output/limited/20230707_032329/` に置き、Git管理下にある（サンプルCSV `*_sample_*.csv` のみ管理外）。

### 1.3 結果の一般化可能性の限界

本ドキュメントの全ランは **ハノイROI・30m・単一観測日（2023-07-07T03:23:29Z）** の結果である。したがって次の点は**検証されていない**。

- **季節・時刻**: 乾季／雨季、他の時刻の観測での再現性。植生指数と土地被覆の関係は季節依存が大きいと予想されるが、本研究では未確認
- **他都市**: ベトナム他都市および他国の都市での再現性
- **他スケール**: 90m・300mでの再現性。特に土地被覆の面積率は30mで二値化しており（5.5.1節）、粗いスケールでは性質が変わる

「分光指数が被覆率型を上回る」（4.3節）を含む本ドキュメントの結論は、**上記の条件下での観察**であり、条件を変えた場合の一般性を主張するものではない。

### 2.1 台帳の読み方（比較してよい組み合わせ）

- **ラン3〜5 は母数が完全に一致し（1,856,120）、10万件サンプルの `cell_id` も100%一致する**。非NULLを要求するフィルタ列を変数セットに依らず一定にしているためであり（3.3節）、**変数セットの比較は同一セル上で行われている**。本ドキュメントで最も統制の効いた比較である
- **ラン5・11〜13（建物高さ軸）も母数が完全に一致し（1,856,120）、10万件サンプルの `cell_id` が100%一致する**。投入する高さ列が1本でも、非NULLを要求するフィルタ列は `BUILD_H_MEAN`・`BUILD_H_MAX` の両方のまま変えない設計による（3.2節）。**建物高さ構成の比較も同一セル上で行われている**
- **ラン6・7 も相互に母数・サンプルが一致する**（1,856,176）
- **母数が異なるラン間はサンプルもほぼ別物になる。** `sample_dataset` は母数に対して位置指定で抽出するため、母数が数十セル違うだけで抽出位置が総入れ替えになる。実測の `cell_id` 重なりは ラン5対ラン6・7 が **6.05%**、ラン5対ラン8・9 が **5.33%** であり、事実上独立な2標本とみなすべきである（10万/185万 = 5.4% が偶然一致の基準値）。**土地被覆ソース軸・人口ソース軸の比較は、変数セット軸と違って標本統制されていない**
- **ラン1・2 と ラン3以降は母数が異なる**（1,901,915 対 1,856,120）。拡張により土地被覆・人口密度・夜間光の欠測が加わったためで、差は 45,795セル（2.41%）である。世代をまたぐ数値比較は参考にとどめる
- **ラン5・8・9（人口ソース軸）は母数が揃っていない**（1,856,120 対 1,864,640、差 8,520セル・0.46%）。フィルタ列は「選択した人口版のみ」を要求する設計であり、投入しない版の欠測で母数を減らさないことを優先した
- ラン6・7（Esriソース）とラン3〜5（GLCソース）は入力データセットが別であり、母数がわずかに異なる（差 56セル）

## 3. ラン間で共通の処理条件

現時点では以下の条件は全ランで共通である。ランによって変わるようになった項目は、2節の台帳へ列として移す。

### 3.1 ROI・スケール・観測日・格子

- ROI: ハノイ
- スケール: **30m**
- 観測日: **`2023-07-07T03:23:29Z`**（単一観測日）
- 格子: 30m正準グリッド（全 **3,739,454行**）。Satellite Only と同一の格子であり、`cell_id` で結合する

### 3.2 建物高さ列の補完

`BUILD_H_MEAN`/`BUILD_H_MAX` は、高さが取れる建物が1つも無いセルでNULLになる。「建物が無い」の判定は `BUILD_COV == 0`（被覆率）単独ではなく、`BUILD_COV == 0 AND BUILD_DEN == 0`（棟数密度も0）で行う。

`BUILD_COV` はfineグリッドへのラスタ化による近似であり、`gis_data_buildings.md`「小さい建物の取りこぼし」の実測によれば、30mでは建物の重心が存在するセル（`BUILD_DEN > 0`）の**14.0%**で `BUILD_COV == 0` になる（GBAの建物の80.7%が100m²未満で、fine 10mセルの中心を1つも含まない場合に被覆率へ寄与しないため）。`BUILD_DEN` は高さ集計と同じ建物重心の帰属方式であるため、`BUILD_COV` 単独より「建物が無い」の判定に適する。`BUILD_COV == 0` のみを基準にした場合、実データで16セル（有効域内）が誤って0補完される（`BUILD_DEN > 0` なのに `BUILD_COV == 0` かつ高さNULL）ことを確認した。

この2条件のANDに基づき、`BUILD_COV == 0 AND BUILD_DEN == 0` のセルのみ「建物が無い ⇒ 建物高さ0m」として0補完し、`BUILD_COV > 0` または `BUILD_DEN > 0` なのに高さNULL（真の欠落）のセルは補完せず、後段の非NULL要求フィルタで除外した。

データセット全体（3,739,454セル）での補完件数: **2,781,918セル（74.4%）**。ラン1のフィルタ後母数における補完セルは 1,513,657セル（79.6%）、ラン2 では 243,627セル（38.6%）。

**補完はどの建物高さ構成でも同一に行う。** 下記の `--building-height` は「補完後の2列のうち、どれをモデルへ投入するか」だけを切り替えるものであり、補完の判定条件・件数には影響しない。

#### 建物高さ列の構成（`--building-height`）

`BUILD_H_MEAN` と `BUILD_H_MAX` は同一の建物ポリゴンから集計した高さであり強く相関するため（Pearson +0.986・6.2節）、2列とも投入するとVIFが危険水準を大きく超える（6.4節）。投入する高さ列は `--building-height` で切り替える。ラン別の値は2節の台帳「建物高さ」列を正本とする。

| 値 | 投入する列 | 備考 |
|---|---|---|
| `both` | `BUILD_H_MEAN` + `BUILD_H_MAX` | ラン1〜10 の構成 |
| `mean` | `BUILD_H_MEAN` | **採用構成（既定）**。セル内の平均建物高さ |
| `max` | `BUILD_H_MAX` | セル内の最高建物高さ |
| `pc1` | `BUILD_H_PC1` | 2列を標準化して合成した第1主成分（合成列） |

全構成に共通する仕様は次のとおり。

- **非NULLを要求するフィルタ列は構成に依らず高さ2列のまま**であり、母数・分析サンプルは構成間で完全に一致する（2.1節）
- **相関行列の対象列は構成に依らず一定**（拡張後の全候補列）であり、`BUILD_H_PC1` は対象に加えない。診断すべきは元の2列の相関そのものであるため（6.2節）
- `pc1` の主成分は**分析サンプル全体で1回fitする**（Spatial CVのfold内ではfitし直さない）。符号は `BUILD_H_MEAN` への寄与が正になる向きへ揃える。loadings・寄与率・標準化統計は`*_results.json` の `building_height_pc1` に記録する。実測値と fold 内 fit を採らなかった根拠は6.4節
- 出力ファイル名の `_bh_{構成}` は **`both` のときだけ付けない**。既定を変えても`both` で実行済みのランの出力名が動かないようにするためである（3.7節）

### 3.3 品質管理（フィルタ条件）

全ランに共通して、以下を満たすセルを残す。

- `IN_ANALYSIS_AREA == 1`
- 指定した列と `LST` が非NULL（建物高さ補完後）
- `LST_VALID_RATIO >= 0.5`

`VALID_GIS_MASK == 1` を追加で課すかどうかはランごとに変わるため、台帳の「フィルタ条件」列で示す。

`VALID_GIS_MASK == 0` は全件 `no_gis_feature`（`build_dataset.py` のコメントにより「分析上は0として扱ってよい」観測結果）であり、`missing_gis_data` は0件だった。**ただしこの「0件」は、建物パラメータテーブルが正準グリッドの全セルに結合できたこと（テーブル結合の完全性）を示すのみであり、GBAが現地の建物を漏れなく検出できていること（データそのものの正確性・有効カバレッジ）までは検証していない**（`BUILD_COV`/`BUILD_DEN` は結合の有効域外でも常に0.0を返す設計のため、結合が成功していれば `missing_gis_data` は構造的にほぼ0件になる。3.2節で述べた小規模建物の取りこぼしはこの「0件」では検出できない）。

この限界を踏まえたうえで、**主結果では `VALID_GIS_MASK` を課さず有効域全体を対象**とする（`VALID_GIS_MASK == 0` のセルを「GIS特徴量が観測結果として0」として扱う判断自体は妥当であり、テーブル結合の完全性は確認済みのため）。判断の妥当性は6.6節で検証する。

### 3.4 サンプリング

- 適用順序: 建物高さ補完 → フィルタ → サンプリング → ブロック割り当て（ブロック割り当てを先にすると各ブロックのセル数が不均等に減り、fold のサイズ均衡が崩れるため）
- サンプル数: `100,000`
- 乱数シード: `42`
- サンプル内の建物高さ補完セル数: ラン1 **79,593件**、ラン2 **38,552件**

  この値は3.2節の「フィルタ後母数における補完セル数」とは異なる母集団（フィルタ後の全件 vs 10万件サンプル）に対する集計であり、両者は一致しない（比率はほぼ一致: ラン1 79.6% vs 79.6%、ラン2 38.6% vs 38.6%）。研究記述で引用する際はどちらの母数か明記すること。

### 3.5 モデル設定

- 学習 / テスト: `80,000 / 20,000`（random split、`test_size=0.2`）
- 目的変数: `LST`（°C）
- MLR: 説明変数・目的変数の両方を標準化（標準化偏回帰係数として解釈）
- RF: `n_estimators=300`, `min_samples_leaf=5`
- Spatial CV:
  - `5-fold`（Group K-Fold、group = 空間ブロックID）
  - ブロックサイズ: `2,700m`
  - 非空ブロック数: ラン1 305、ラン2 299（10万件サンプル後ベース）
- SHAP: 評価サンプル `2,000`、background `500`

### 3.6 分散0の特徴量列の除外

説明変数のうち分析サンプル内で分散が0になる列は、VIF算出・モデル学習の前に除外する。定数列を残すと `compute_vif` の補助回帰が決定係数1.0を返し、**VIFが `inf`（完全共線）と報告される**が、これは実体のある共線性ではなく定数列に起因する偽陽性であり、多重共線性の診断そのものを汚染するためである。

GLC を土地被覆ソースとするラン（4・5・8・9・10）では `LULC_BARE_COV` が除外された。ハノイROIのGLC_FCS30Dには裸地クラス（200・201・202）の画素が1つも存在せず、全セルで厳密に0.0になるためである。**Esri を用いたラン（6・7）では裸地画素が存在するため除外は発生しない**。除外した列名は各ランの `*_results.json` の `dropped_constant_features` に記録している。

判定は母集団ではなく分析サンプル（10万件）に対して行う。VIF も同じサンプルで算出するため判定対象を揃える必要があるが、代償として母集団での出現頻度が低いクラスはサンプル依存で除外されうる。

GLC_FCS30D は30mで1セルあたり1.08画素であり、クラス別面積率が実質的に0/1の二値へ退化する。Esri 10m は9.08画素/セルで真の集約が成立するため、**被覆率型が不利な条件で評価されている可能性**を検証した。

| 指標 | GLC | Esri | 差 |
|---|---|---|---|
| `coverage` の RF R²（Spatial CV） | 0.7483 | 0.7314 | **-0.017** |
| 被覆率ブロック SHAP 合計（`coverage`） | 0.9311 | 1.0277 | +0.097 |
| `LULC_BUILT_COV` の SHAP（`coverage`） | 0.654 | 0.806 | +0.152 |

### 5.5.1 二値化の度合いの実測（想定と逆の結果）

計画段階では「1セルあたり画素数」（GLC 1.08 / Esri 9.08）から、Esri では真の集約が成立すると想定していた。実測はこれと逆だった。

| ソース | 面積率が 0 か 1 に張り付くセルの割合（7クラス平均） |
|---|---|
| GLC_FCS30D | 93.41% |
| Esri 10m | **95.84%** |

**画素数が9倍あっても、二値化はむしろ強い。** 土地被覆が空間的に強く自己相関しており、30mセル内の9画素がほぼ同一クラスになるためと解釈できる。**「1セルあたり画素数」は真の集約が成立する度合いの指標として過大評価になる**（[calc_urban_params_io_spec.md](../02_methods/calc_urban_params/calc_urban_params_io_spec.md) 6.4節が記録する画素数は、この限界を伴って読む必要がある）。

なおクラス別の分布はソース間で大きく異なる。`LULC_BUILT_COV` は GLC 平均 0.159（0の割合 77.4%）に対し Esri 平均 0.321（63.3%）であり、**Esri は市街地を約2倍広く分類する**。`LULC_CROP_COV` は逆に GLC 0.677 に対し Esri 0.478 である。

### 5.6 人口密度データソースの差し替え

| 版 | 人口概念 | 観測年 | SHAP寄与 | RF R²（Spatial CV） |
|---|---|---|---|---|
| WorldPop2020 | 居住人口 | 2020 | **0.2048** | **0.8267** |
| LandScan2020 | 実効人口 | 2020 | 0.1051 | 0.8212 |
| LandScan2023 | 実効人口 | 2023 | 0.1895 | 0.8223 |

**解釈上の制約（2点）**:

1. **人口概念の差と観測年のずれを1つの比較で分離できない。** WorldPop2020 と LandScan2020 の比較は観測年を固定して概念を変え、LandScan2020 と LandScan2023 の比較は概念を固定して年を変える。しかし WorldPop はベトナムの提供が2020年までであり、居住人口側で年を振ることができないため、「概念×年」の2元配置は成立しない。したがって WorldPop が最も高い寄与を示したことを「居住人口のほうが実効人口よりLSTをよく説明する」と読むことはできない
2. **母数が揃っていない**（WorldPop 1,856,120 対 LandScan 1,864,640、差 8,520セル・0.46%）。フィルタ列は選択した人口版のみを要求する設計であり、**人口ソース軸のみ母数統制されていない**（2.1節）

なお LandScan は2020から2023の3年間で SHAP 寄与が 0.105 → 0.190 とほぼ倍増するが、RF R² はほぼ変わらない（0.8212 → 0.8223）。

### 5.7 符号の解釈

`NDVI`・`NDWI` は標準化係数が負（冷却方向）、`NDBI`・`BUILD_COV`・`BUILD_H_MEAN`・`ROAD_DEN` は正（昇温方向）であり、植生・水域が冷却、建築・道路が昇温という直感的に妥当な符号関係を示す。

**建物高さ2列の符号の逆転は、共線性のアーティファクトだった。** ラン1では `BUILD_H_MAX` の係数が負（-0.031）で `BUILD_H_MEAN` と逆転しており、当初は「単純な解釈が難しい」と整理していた。その後、高さ列を1本に絞ったラン11〜13 をラン5と同一セル上で比較したところ、**逆符号の一対（+0.126 / −0.144）は共線性を解消すると消え、係数はほぼ0へ収束した**（6.4.3節）。**建物高さの符号は解釈の対象にならない**と読むべきであり、冷却・昇温の符号関係として意味を持つのは分光指数・被覆率・道路・標高である。

`ELEV_MEAN` の係数が負（標高が高いほどLSTが低い）であるのは、標高上昇に伴う気温低減という一般的な傾向と整合する。

### 6.4 建物高さ列の多重共線性（解消済み）

#### 6.4.1 問題の所在

計画段階で懸念していたとおり、`BUILD_H_MEAN`/`BUILD_H_MAX` のVIFは極めて高い値（ラン1 41.38/47.56、ラン2 36.24/41.42、ラン5 46.74/54.86。慣例的な危険水準 VIF > 10 を大きく超える）を示した。直接の原因は2列の Pearson **+0.986**（6.2節）であり、同一の建物ポリゴンから平均と最大を集計している以上、構造的に避けられない相関である。建物高さの0補完（`BUILD_COV == 0 AND BUILD_DEN == 0` のセルへの適用）により「高さ0」の大きなスパイクが2列に共通して生じることも、相関をさらに押し上げている。

**拡張では解消しなかった**: 建物高さ2変数のVIFは全8ランで 32.9〜60.2 の範囲にあり、変数セット・土地被覆ソース・人口版のいずれを変えても高止まりした（6.1節）。特筆すべき点は次の3つである。

- **変数セットに依存しない**: `spectral` 54.8/46.7、`coverage` 54.8/46.7、`both` 54.9/46.7 とほぼ不変。ラン3〜5 は同一セル上の評価であり（2.1節）、新規変数の追加・削除と無関係な独立した問題であることが標本統制のうえで確認できた
- **Esri での高い値（60.2/51.4）は Esri に起因しない**: 土地被覆を1列も投入しない共通ベース8変数のみで VIF を再計算しても GLC標本 54.81 / Esri標本 60.15 と同じ差が出る。**差の正体は標本の違い**であり（重なり 6.05%）、土地被覆ソースの性質ではない。LULC 5クラスを加えた影響は `BUILD_H_MEAN` で 51.17 → 51.38 にとどまる。**「解像度を上げると建物高さの共線性が増す」という読みは誤りである**
- **`VALID_GIS_MASK == 1` 限定で最小になる**: 37.6/32.9（ラン10）。建物が存在するセルに限定すると「高さ0のスパイク」が減るためと解釈でき、0補完に起因するという説明と整合する。ただしラン10 も母数が異なり標本が別であるため、低下幅そのものは標本変動を含む

#### 6.4.2 3構成の比較（ラン11〜13）

高さブロックの構成だけを差し替えた3構成を、**ラン5と同一セル上**で評価した（母数・`cell_id` とも完全一致。2.1節）。

| 構成 | 建物高さのVIF | RF R²（Spatial CV） | Linear R²（Spatial CV） | RF重要度（高さ計） | SHAP平均絶対値（順位） | 標準化係数（順位） |
|---|---|---|---|---|---|---|
| ラン5 `both` | **46.74 / 54.86** | 0.8267（sd 0.0226） | 0.7647 | 0.0068 | 0.0193（第10位）/ 0.0132（第12位） | **+0.126（第7位）/ −0.144（第6位）** |
| ラン11 `mean` | **2.46** | 0.8266（sd 0.0226） | 0.7644 | 0.0052 | 0.0291（第10位） | −0.0028（第15位） |
| ラン12 `max` | **2.89** | 0.8266（sd 0.0225） | 0.7645 | 0.0052 | 0.0302（第10位） | −0.0110（第14位） |
| ラン13 `pc1` | **2.68** | 0.8266（sd 0.0226） | 0.7644 | 0.0052 | 0.0295（第10位） | −0.0066（第14位） |

**3構成とも建物高さのVIFが危険水準を大きく下回った**（2.46〜2.89）。

**VIF値そのものの精度**: 6.4.1節の検証から、10万件サンプルにおける建物高さのVIFは標本の取り方だけで 54.8〜60.2 の幅（約10%）で変動する（2.1節）。本ドキュメントのVIFは「危険水準（>10）を大きく超えるかどうか」の判定には十分だが、**ラン間の数ポイントの差を実質的な違いとして解釈してはならない**。3構成の差（2.46〜2.89・幅0.43）もこの範囲にあり、**VIFの大小を採用構成の決め手にはしない**。

**説明力はどの構成でも変わらない。** RF R²（Spatial CV）の差は最大 **0.0001** で、fold間sd（0.0226）の約1/200である。上位変数の順位（`LULC_BUILT_COV` → `NDBI` → `NDVI` → `ELEV_MEAN` → `POP_DEN_WORLDPOP2020` → `NTL_MEAN`）は4構成で完全に一致し、値の差もすべて 0.001 未満である（差はいずれも 0.0002 以下。たとえば `LULC_BUILT_COV` はラン5 0.5294 に対しラン11〜13 が 0.5296）。建物高さブロックがRF重要度に占める割合は 0.52〜0.68% にとどまるため、この一致は当然の結果である。**R²の差を採否の根拠にしてはならない。**

#### 6.4.3 最も重要な所見: `both` の標準化係数は共線性のアーティファクトだった

上表で唯一、構成間に明確な差が出たのは**標準化係数**である。

- ラン5 `both` では `BUILD_H_MEAN` **+0.126**（第7位）と `BUILD_H_MAX` **−0.144**（第6位）という、**大きさが同程度で符号が逆の一対**が現れていた。これは分散拡大による典型的な共線性アーティファクトである
- 共線性を解消した3構成では、いずれも係数がほぼ0（**−0.0028〜−0.0110**、第14〜15位）へ収束した

**ラン5で建物高さが標準化係数の第6・7位に現れていたのは見かけの効果であり、実際の寄与ではなかった。** これは同一セル上の比較で示された結果であり（標本差では説明できない）、RF重要度・SHAPが一貫して建物高さを小さな寄与（第10位前後・全体の1%未満）と評価していたことと整合する。**線形回帰の標準化係数を主たる解釈に用いなかった従来の判断（6.4.5節）が、事後的に正しかったことが確認できた。**

#### 6.4.4 採用構成: `mean`（セル内の平均建物高さ）

3構成は統計的にほぼ等価であるため、**VIF・解釈可能性・標準化係数**で判断した。採用は **`mean`** とし、`--building-height` の既定値もこれに合わせた。

| 判断軸 | 評価 |
|---|---|
| VIF | `mean` 2.46 が最小。ただし3構成の差は標本変動の範囲内であり、決め手にはしない（6.4.2節） |
| 解釈可能性 | **`mean` は「セル内の平均建物高さ」として物理的な意味が直接読める。** 都市キャノピー高さに対応する標準的な都市形態パラメータであり、`urban_structure_parameters.md` の定義をそのまま使える |
| 実装上の但し書き | **`mean` は生の観測列であり、主成分化に伴う但し書き（fit範囲・符号正規化・fold内fitの是非・無次元の合成軸）が一切不要**。結果の再現・解釈に必要な前提が最も少ない |
| 情報損失 | `pc1` は2列の情報を99.3%保持するが（寄与率 0.9930）、`mean` を採っても説明力・重要度・SHAPは `pc1` と区別できない（6.4.2節）。情報損失は実測上ゼロと見なせる |

**`max` を採らなかった理由**: SHAP平均絶対値がわずかに大きい（0.0302 対 `mean` 0.0291）が、この差は建物高さブロック内での順位を変えず（いずれも第10位）、全体順位にも影響しない。一方 `max` はセル内の単一の建物に値が左右されるため外れ値の影響を受けやすく、平均高さより頑健性が劣る。

**`pc1` を採らなかった理由**: 無次元の合成軸であり、係数・SHAPの値を物理量として読めない。加えて、標準化統計・loadings・符号の向き・fitの範囲という4つの但し書きが結果の解釈に常に付随する。情報保持の利点（99.3%）に見合う実益が実測で確認できなかった。

**Spatial CV の fold 内で PCA を fit する案は採用しなかった**（`pc1` 自体を採らなかったため実質的に無効化されたが、判断の記録として残す）。全体fitとfold内fitの差は「高さ2列の標準偏差の比」だけに限定される。模擬データでの実測 ΔR² は線形回帰 2.6e-08〜2.6e-06・RF 1.7e-05〜2.2e-04 であり、最大値でもラン5のfold間sd（0.0226）の約1/100、かつRF自身の乱数シードによる振れ幅（1.6e-03）より小さい。`src/common/analysis_runs.py`（Satellite Only と共用）へfold内変換の仕組みを持ち込むコストに見合わないと判断した。

> **上記の ΔR² の出典**: 計画段階に複数条件（分割の偏らせ方・乱数シード）で実施した**模擬データによる実測**であり、本リポジトリには再現用の成果物を残していない。**リポジトリ内で再現できるのは線形回帰の1条件のみ**で、`tests/analysis/test_analysis_rq3_limited.py` の `test_whole_sample_fit_agrees_with_fold_internal_fit` が `ΔR² < 1e-4` と `corr(fold PC1, 全体 PC1) > 1 - 1e-6` を固定している（RFは自身のシード変動に埋もれるためテスト対象外）。**RF側の範囲を再検証する場合は測り直しが必要である。**

#### 6.4.5 標準化係数を主たる解釈に用いてよいかの判断

**建物高さブロックについては解消した。** ラン11〜13 では建物高さのVIFが 2.46〜2.89 と危険水準を大きく下回り、係数の解釈を妨げる要因は無い。6.4.3節のとおり、共線性を解消した後の建物高さの寄与はほぼ0であり、これがLSTに対する建物高さの実際の説明力である。

**モデル全体については解消していない。** ラン11〜13 でも `NDVI` 25.0・`NDWI` 26.0 が危険水準に残る（6.1節・6.5節）。分光指数の共線性は本Issueの対象外であり、**モデル全体として標準化係数を主たる解釈に用いてよい状態にはなっていない**。Satellite Only の既存結果と同じ方針を継続し、**変数重要度の主たる解釈は Random Forest の重要度と SHAP に基づき、線形回帰の標準化係数の絶対値順位は補助的な情報として扱う**。

#### 6.4.6 検討対象外とした案

以下の2案は着手時に却下根拠つきで検討対象外としたものであり、記録として残す。

- **`BUILD_COV`/`BUILD_DEN` の除外**: 建物高さのVIFの直接の原因は高さ2列どうしの相関（+0.986）であり、`BUILD_COV` × `BUILD_H_MAX` の +0.766・`BUILD_COV` × `BUILD_H_MEAN` の +0.733（6.2節）はそれより弱い。実際、ラン11〜13 は `BUILD_COV`・`BUILD_DEN` を残したまま VIF が 2.46〜2.89 まで下がっており、**この2列を除外する必要が無いことが実測で確認された**
- **0補完の再設計**: 0補完をやめると「建物はあるが高さが得られない」セルと「建物が無い」セルを区別できなくなり、フィルタで大量のセルが脱落して有効域が大きく縮む（データセット全体の74.4%が補完対象・3.2節）。有効域の縮小は本シナリオの評価意図に反する

**相関行列（6.2節）は据え置く。** 相関行列の対象列は建物高さ構成に依らず「拡張後の全候補列」で一定であり（3.2節）、ラン11〜13 の相関行列はラン5とバイト単位で一致する（対象行数も 98,983 で同一）。したがって6.2節の記述は本節の変更後も有効であり、更新の必要は無い。

### 6.5 分光指数間の共線性

`NDVI`・`NDWI` のVIF（ラン1 22.31・21.17、ラン2 21.49・16.76、ラン5 24.96・25.99）も Satellite Only の既存結果（21.09・20.05）と同水準の高さであり、同じ植生指標間の共線性が継続している。直接の原因は `NDVI` × `NDWI` の Pearson -0.966（6.2節）である。

### 6.6 VALID_GIS_MASK を主結果に課さなかった判断の妥当性

3.3節の実測（`VALID_GIS_MASK == 0` が全件 `no_gis_feature` で `missing_gis_data` が0件）を踏まえ、主結果ではこの条件を課さなかった。ただしこの「0件」という実測は、建物パラメータテーブルの結合が正準グリッド全体に対して完全であることの確認に過ぎず、GBAが現地の建物を漏れなく検出できていることまでは保証しない（3.2節・3.3節）。この限界を踏まえてもなお、`VALID_GIS_MASK == 0` のセルを観測結果として0扱いする判断自体は妥当と考えられる。

台帳の比較から、この判断により Spatial CV R²（RF）はラン1 0.7801 対 ラン2 0.7233 と、有効域全体を対象にした方が高い説明力を示すことが確認できた。拡張後も同じ傾向であり、ラン5 0.8267 対 ラン10 0.7937 と有効域全体が上回る（母数は 1,856,120 対 626,796）。これは「Limitedシナリオが農地・水域を含む多様な土地被覆下でLSTをどれだけ説明できるか」という評価意図と整合する。

## 7. 今後の研究の方向性

- **Full シナリオへ進む**: 測量GISを加えた Full が Limited をどれだけ改善するかを、同じ共通モジュール（`src.common.*`, `src.common.analysis_runs`）を再利用して確認する
- **分光指数間の共線性の解消**: 建物高さの共線性は `--building-height mean` の採用で解消したが（6.4節）、`NDVI`・`NDWI` のVIF（25.0・26.0）は未解決のまま残る。両者の Pearson は −0.966 であり（6.2節）、モデル全体として標準化係数を主たる解釈に用いるには、建物高さと同様の構成比較が要る
- **採用構成の他シナリオへの波及**: Limited で `mean` を採用したことを踏まえ、Full シナリオでも同じ構成を用いるかを、測量GIS由来の建物高さの精度と合わせて判断する
- **GBAの有効カバレッジそのものの検証**: 3.3節で指摘したとおり、`missing_gis_data == 0` はテーブル結合の完全性のみを示し、GBAが現地の建物を漏れなく検出できているかは未検証である。別途、現地測量データや高解像度衛星画像との突合による検証を検討する
- **30mでの観測日拡張**: Satellite Only と同様、複数観測日が揃った時点で同じ経路での複数日比較を検討する
- **Satellite Only との定量比較**: 6.7節の参考比較を、正式な改善幅の評価として別Issueで扱う
- **結果ドキュメントの共通様式の規約化**: 本ドキュメントで導入した台帳形式（列定義・数値の正本の置き方・分割基準）を規約として定め、`satellite_only_analysis_results*.md` へも適用することを別途検討する
- **人口ソース軸の母数統制**: 5.6節のとおり人口ソースの比較のみ母数が揃っていない（差 0.46%）。人口ソースを比較軸として本格的に扱う場合は、フィルタ列に3版すべてを含める設計へ変更するか、母数差を補正する方法を検討する
- **土地被覆ソース・人口ソースの標本統制**: 2.1節のとおり、ソース差し替えランは母数がわずかに違うだけで標本がほぼ別物になる（重なり 5〜6%）。ソース間を厳密に比較するには、共通するセルに限定して評価する仕組みが要る
- **被覆率型変数の位置づけの再検討**: 4.3節・5.5節のとおり、被覆率型は分光指数を上回らず、土地被覆ソースの解像度を上げても結論は変わらなかった。`both` 構成の分光単体に対する改善が 0.017〜0.025 と小さいことを踏まえ、被覆率型を最終的な変数セットに含めるかどうかを、モデルの簡潔性とのトレードオフとして別途判断する

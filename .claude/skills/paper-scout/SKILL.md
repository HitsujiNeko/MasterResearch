# 文献候補探索スキル（引用スノーボーリング）

登録済み文献（S1-S8）の引用関係を OpenAlex でたどり、RQ1-3 に関連する**未登録**の
文献候補を提示する。本スキルは**探索と提示まで**を担い、候補の採否判断・精読・登録は
研究者が [/add-paper](../add-paper/SKILL.md) で行う。

探索ロジックは [src/literature/paper_scout.py](../../../src/literature/paper_scout.py) に実装済み。
本スキルはその実行と結果提示のオーケストレーションを行う。

## 前提: OpenAlex アクセス

- 認証は**任意**。環境変数 `OPENALEX_API_KEY` があれば付与し無料枠が10倍になる。
  未設定でも本用途の想定利用量は未認証の無料枠内に収まる（単一取得は無料枠を消費せず、
  list+filter は未認証でも 1,000回/日）。
- API キーは秘匿情報。**リポジトリに記載せず環境変数で扱う**。ログ・出力には出さない。
- HTTP 429（無料枠超過）は探索を停止せず、当該リクエストをスキップして続行する。

## 実行手順

以下のチェックリストをコピーして進捗を追跡する:

```text
- [ ] Step 1: 起点の確認
- [ ] Step 2: 探索スクリプトの実行
- [ ] Step 3: 候補の提示
- [ ] Step 4: /add-paper への導線
```

### Step 1: 起点の確認

- ユーザーが起点 S 番号を指定した場合はそれを用いる（例: `S1,S5`）。指定が無ければ全件（S1-S8）を起点とする。
- 実行前に、大量の被引用を持つ起点（レビュー論文 S7 等）では取得件数が多くなりうる旨を一言添える。`--max-forward`（既定 400）で1起点あたりの前方引用上限を調整できる。

### Step 2: 探索スクリプトの実行

出力先はスクラッチパッド（探索メモはリポジトリ非コミット）とする。パスはセッションのスクラッチパッドディレクトリを使う。

```sh
python -m src.literature.paper_scout \
  --s S1,S5 \
  --top 20 \
  --output "{スクラッチパッド}/paper_scout_candidates.csv"
```

実行はプロジェクトルートから `python -m` 形式で行う（`python src/...` は import を壊すため使わない）。

- `--s` を省略すると全件（S1-S8）起点。
- 候補が多い場合は `--min-score {閾値}` で足切りする（既定 0.0＝除外なし）。スコアはキーワードの機械的一致度であり、全起点だと数百〜千件規模になりうるため、`--min-score 30` 等で上位帯に絞ると扱いやすい。表示・CSV の両方に適用される。
- API キー未設定で polite pool を使いたい場合のみ `--mailto {メールアドレス}` を付与する（キー設定時は不要）。
- 標準エラーに「解決できなかった起点」が出た場合はそのまま提示する（DOI なし S2 等はタイトル検索で解決できないことがある）。

### Step 3: 候補の提示

- スクリプトが標準出力する Markdown テーブル（スコア降順・上位 `--top` 件）をそのまま提示する。列は「スコア・タイトル・年・誌名・DOI・経由S番号・方向（前方/後方）」。
- `--min-score` 適用後の候補が `--output` の CSV に保存される旨を伝える（表示・CSV とも同じ閾値後の候補が対象）。
- **スコアはあくまで RQ キーワードの機械的な一致度**であり、関連性の最終判断ではないことを明記する。

### Step 4: /add-paper への導線

- ユーザーが精読したい候補を選んだら、claude.ai（Claude Projects）での精読 → 構造化要約生成 → [/add-paper](../add-paper/SKILL.md) での登録、という既存フローにつなぐ。
- 本スキルは登録を行わない。DOI を /add-paper に渡せば書誌照合（Crossref）から登録まで進められる。

## 注意事項

- スコアリングのキーワード・重みは [paper_scout.py](../../../src/literature/paper_scout.py) の `KEYWORD_WEIGHTS` で定義。研究の関心に応じて調整してよい（変更時はテストを更新する）。
- 候補の関連性・採否は研究者が判断する。スキルは探索と提示にとどまる。
- 起点 DOI が非DOI形式（一部の掲載誌 URL）や未記載の場合、スクリプトはタイトル検索で解決を試みる。曖昧な起点はスキップされ、標準エラーに記録される。

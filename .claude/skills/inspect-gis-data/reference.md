## メタデータ提示フォーマット（Step 1）

`build_data_inventory --path` の JSON 出力を、以下の要点に整理して提示する。

### ベクタ（GPKG / SHP / GeoJSON 等）

| 項目 | 値の例 | 備考 |
|---|---|---|
| ファイル | `data/gis/survey/merge_DH.gpkg` | 相対パス・サイズ・更新日時 |
| CRS | `EPSG:4326` / 空文字 | 空文字時は Step 2 の `get_layer_crs` で確定 |
| レイヤ | `elements` | 複数レイヤなら各行に展開 |
| ジオメトリ種別 | `Point` / `Unknown` | `Unknown` は混在の可能性（DGN 由来等） |
| 地物数 | 104,317 | レイヤごと |
| 属性スキーマ | `Text:str`, `Level:int32` … | 分析利用可能な属性の当たりを付ける |
| bbox | `[minx, miny, maxx, maxy]` | ROI との重なり判断に使う |

### ラスタ（GeoTIFF 等）

| 項目 | 値の例 | 備考 |
|---|---|---|
| CRS | `EPSG:4326` | |
| bbox | `[left, bottom, right, top]` | |
| 解像度 | `[xres, yres]` | LST は 30m 想定 |
| サイズ | width × height, band 数 | |
| nodata / dtype | `-9999` / `float32` | 値域確認は QGIS の `get_raster_info` で補完 |

- `error` キーがある場合は読み取り失敗。破損・非対応ドライバ等を疑い、原因をユーザーに提示する

## 確認チェックリスト（Step 3）

目視確認の観点。各項目について「事実」を記録し、可否の断定は避ける。

### 1. カバレッジ

- [ ] データの範囲は ROI を**覆っているか**（全域 / 一部のみ / ROI 外にはみ出す）
- [ ] 有効域は ROI 全体と一致するか（**ROI 全体と同一視しない** — CLAUDE.md 用語集）
- [ ] 空白域・欠測域はあるか

### 2. 属性（ベクタ）

- [ ] 分析に使える値を持つ属性はどれか（標高値・区分コード・面積・名称など）
- [ ] 属性値の内容は判読できるか（エンコーディング崩れ・コード体系不明はないか）
- [ ] 空値・既定値ばかりの属性はどれか

### 3. CRS

- [ ] `get_layer_crs` で CRS は正しく認識されているか（`authid` が空でも proj4/description で判断する）
- [ ] CRS 未定義（`authid`・`proj4` 空）の場合、想定 CRS を `set_layer_crs` で設定したか
      （ベトナム測量データは VN-2000 / UTM zone 48N = `EPSG:3405`）
- [ ] 設定後、代表点を `transform_coordinates` で EPSG:4326 に変換し ROI 域内に落ちるか確認したか
- [ ] VN-2000 等の投影座標系の場合、ROI（EPSG:4326）と正しく重なるか

### 4. ジオメトリ

- [ ] ジオメトリ種別は想定どおりか（Point/Line/Polygon、混在の有無）
- [ ] 不正ジオメトリ（自己交差・空ジオメトリ）はないか
- [ ] **extent が不自然に広い / 切りの良いダミー座標**（例: `499999.1`, `999999.1`）はないか
      → 外れ値ジオメトリの混入を疑い、地物をサンプリングして実分布を確認する
- [ ] 地物数はデータ仕様と整合するか

### 5. ラスタ固有

- [ ] 値域（min/max）は物理的に妥当か（例: LST は摂氏で妥当な範囲か）
- [ ] nodata の扱いは適切か
- [ ] 解像度は分析スケール（30m 等）と整合するか

## QGIS 操作対応表（Step 2）

詳細は [qgis_mcp_usage_guide.md](../../../docs/02_methods/qgis_mcp_usage_guide.md) の「ユースケース1: データ確認」を参照。

| 目的 | ツール | 備考 |
|---|---|---|
| 接続確認 | `ping` | クラッシュ後は `get_project_info` で状態確認 |
| ベクタ読み込み | `add_vector_layer` | **絶対パス**指定 |
| ラスタ読み込み | `add_raster_layer` | **絶対パス**指定 |
| CRS 確認 | `get_layer_crs` | `authid` 空でも proj4/description で判断 |
| CRS 設定（未定義時） | `set_layer_crs` | 再投影せず解釈を変える。測量データは `EPSG:3405` |
| 座標変換で妥当性確認 | `transform_coordinates` | 代表点を EPSG:4326 化し ROI 域内か確認 |
| 属性・件数確認 | `get_layer_features` | |
| ラスタ値域確認 | `get_raster_info` | min/max/バンド数/extent |
| グループ作成・移動 | `create_layer_group` → `move_layer_to_group` | ROI は `ROI` グループへ |
| 範囲へズーム | `zoom_to_layer` | |
| 描画取得 | `get_canvas_screenshot` | 再レンダリングなしの高速確認。ROI 基準でズーム |
| 保存 | `save_project` | 明示指示がある時のみ。大規模レイヤはこまめに（クラッシュ対策） |

### スクリーンショットの保存先・命名規則

データ取得タスクの検証としてスクリーンショットをコミットする場合の定型。目的・対象範囲の詳細は
[qgis_operation_guidelines.md の「スクリーンショット（視覚的検証記録）の扱い」](../../../docs/02_methods/qgis_operation_guidelines.md#データ取得タスクにおけるスクリーンショット視覚的検証記録の扱い)を正本とする。

| 項目 | 定型 |
|---|---|
| 保存先パス | `images/gis_data/{カテゴリ}/{カテゴリ}_{データセット}_{ROI}.png`（英小文字スネークケース） |
| 例 | `images/gis_data/roads/roads_osm_hanoi.png` |
| 複数枚 | `_overview` / `_detail` 等の接尾辞を付す |
| 取得方法 | 原則 `get_canvas_screenshot`（容量抑制）。高解像度 `render_map` は必要時のみ |
| 構図 | ROI 基準でズームし、カバレッジ・CRS 整合・分布/外れ値が判読できること |
| 対象範囲 | 空間データ（ラスタ・ベクタ）全般。非空間データ（統計 CSV 等）は対象外 |

### 命名規則（qgis_operation_guidelines.md より）

- レイヤーグループ: データカテゴリ名（`ROI`・`建物`・`道路`・`DEM`・`測量データ` 等）
- レイヤー名: データソース略称＋カテゴリ、または技術的識別子をそのまま
- 測量データ: `測量_{略称}`（例: `測量_CS`）

### CRS 方針

- プロジェクト CRS は **EPSG:4326（WGS84）** を基準とする
- 面積・距離計算は都度 UTM 等の投影座標系へ変換（データを恒久再投影しない）
- VN-2000 データは CRS が正しく認識されているか確認し、必要に応じ EPSG:4326 に変換して重ねる
